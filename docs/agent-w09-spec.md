## 2. 周期回顾与合流

- 复用 W08 持久 worker 和去重边界，以宠物、回顾类型、时区、规范窗口和版本识别作业。星期一作为自然周起点，窗口左闭右开。时区来自真实档案字段（存在且有效时），否则采用 Asia/Shanghai。首次启用水位持久化，恢复按 D4，不回补任意历史。
- 使用统一观测查询输出统计、覆盖与缺口，附基线学习状态、活跃目标以及近期主题摘要。回顾运行可返回零条发现。模型判断相关性、表达和主题归并依据；服务端校验事件主体、来源窗口、覆盖、主题引用和交付预算。个人基线比较维持关闭，留给 W11。无数据不推导异常、活动减少或健康；两段实际观测可分别呈现并列事实。
- 设备事实和观测发现分类型持久化。主题保留稳定 ID、类别、打开／持续／恢复状态、起始和更新时间、依据及关联回顾/事件和轨迹。相同事件实例只产生一条首发消息，恢复更新同一主题。新实例须经过前一次恢复或经过可审计的关闭。回顾主题由模型选择既有主题关联或提出新主题，服务端校验同主体，并用归一化事实锚点和窗口避免每日、周回顾重复提报同一事件。
- 进度从 W05 状态变为就绪后生成一次学习完成事件，键包含宠物、维度和版本。以当前状态初始化旧数据水位，生产首启不得把历史已就绪当作新事件。后续新版本重新累计后可报告新的真实转换。

## 3. 硬件规则与客户端迁移

- 从实际归属与绑定生效的设备帧中检测低电、数据失联和长时间无有效读数。沿用客户端配置语义：连续 3 个不同合格帧电量低于 20% 开启（低于 10% 提升严重度），连续 3 帧高于 25% 恢复；云端服务有可用连接且最后一次已接收设备帧过 30 秒才判定设备数据失联；持续无效健康读数按 90 个连续有效上报节拍的口径达到约 3 分钟，恢复用新有效帧。基于实际采样节奏维护首次越界时间与帧去重，长时间无帧进入失联语义，缺字段不计作明确无效。
- 事件状态持久化，旧帧和重复帧不打开新事件。设备换绑、从未在线、后端 MQTT 故障、启动与重连期间不得编造设备事件；启动判断要依赖可用连接和有效设备水位。检测与事件持久作业的耗时不阻塞 MQTT 实时分发。
- 事件运行收到确定性事实与来源，模型只决定表达、相关性和是否值得打扰。代码按助手设置决定真实交付。以伙伴页主题或会话消息承载，入口可追问「为什么提醒我」并下钻证据，铃铛汇总和已读同步留给 W12，推送留给 W13。移除设定页关于主动程度尚未生效的文案。
- 后端提供宠物级受管理规则能力。新 App 在已获知后端接管的情况下仅抑制同一宠物的三类本地重复提醒，不撤除必要的设备状态展示。切宠、退出及无法确认能力时恢复原逻辑。已留存历史可读。
- `review`、`event` 与对话、检查点共用运行循环。两种后台形态只允许相关的事实类工具，不接受委托变更、资料写入、直接外部调用或动作。发布关停状态由后端能力响应与 worker 一致反映。

### 5.1 交付面

- **服务端新域 `server/petsense/agent/care.py`**：主题持久化（`AgentCareTopic`，(pet,kind,category,anchor,instance) 唯一，恢复更新同行、新实例须经恢复或可审计关闭）、硬件规则状态机（`observe_frame`，语义沿用客户端配置：电量 3 个不同合格帧 <20% 开启 / <10% 升级 / 3 帧 >25% 回稳，健康读数 90 连续无效帧 ≈3 分钟、缺字段不计、新有效帧恢复，帧去重由 ingest 序号门保证）、失联扫描（`detect_stale`：连接可用且稳定 ≥30s 且最后已收帧 >30s；从未在线无水位不判定）、换绑关闭（closed_reason=rebind）、学习转换（`learning_events`：水位对比 learning→ready，首扫只初始化、键=维度:版本终身一次、新版本可再学）、回顾窗口计算（`due_daily_window`/`due_weekly_window` 只取最新受影响窗口，D4）与时区解析（真实档案字段存在且有效时用之，否则 Asia/Shanghai；当前档案无时区字段，恒走缺省）。
