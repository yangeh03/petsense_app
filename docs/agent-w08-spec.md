## 2. 产品行为

- 话语可生成事实观察、个人比较、定时回顾三类计划。计划包括关注维度、条件语义与结构化依据、时区、起止和观测时段、提醒安排、结束条件。每条都有截止回信。短于一小时的委托仍在截止时评估，不等待普通检查节流。
- 支持动作、声音和现有聚合能提供的有效体征事实。区域语义未接入时明确说明限制并保留用户选择。个人比较围绕用户确认的数值指标、阈值和时段，须满足 W05 基线就绪及当次覆盖要求。就绪态和基线版本变化在每次评估时重新验证。「先按事实观察」保留实际覆盖，基线合格后按确认计划进入比较。「等基线就绪」只计算真正进入观察后的覆盖；截至期满仍未就绪时如实回信。
- 确认卡展示计划全文和基线选择，可编辑并重新提交归一化计划。创建在确认时生效，确认晚于原定开始时不得把先前窗口算作已观察。委托簿显示状态、当前计划、提醒和回信，深链回原会话。暂停不延长截止，暂停期间的缺口标为未观察。取消终止后续观察与回信。续期须确认新版本；历史计划、回信与来源保留。
- 活跃目标摘要进入氛围快照。时段、日期和条件由用户或模型提出，服务端校验并持久化明确时区与绝对时间。自然窗口左闭右开，默认 Asia/Shanghai。模型不得根据无帧推导零活动或正常。

## 3. 持久化、工具与恢复

- 使用追加式计划版本和稳定委托标识。计划状态覆盖待确认、等待基线、观察中、暂停、到期交付完成与取消；未确认提案不得创建调度任务。每次状态转换绑定用户、宠物及预期计划版本，过期提案或并发旧决策返回最新状态。复用 W03 的提案状态、鉴权和决定入口，分派到受控业务处理器。
- P00 新工具为 `read_task` 和 `propose_task_change`。前者只读本宠委托及交付，后者只生成或更新候选，由已鉴权的用户决定执行。检查点的工具能力仅含所需的事实读取与受约束的结构化交付，设备、外部搜索、资料写入、委托变更和任意记忆写入均由矩阵拒绝。
- 在 SQLite 持久记录检查点、下次到期、观测水位、执行状态、尝试次数和稳定结果键。调度器启动时恢复待执行和重启中断任务。只在模型运行前后使用短数据库事务；输入包含物化观测、实际覆盖与缺口、计划版本和可选基线版本。优先到期，普通检查基于时间和数据水位合并。到期重试有界，建议首版一次重试并保持到期优先。
- 模型检查点复用 W01 循环和运行轨迹，输出继续观察、候选提醒或到期回信。代码用已物化证据校验结果是否可交付，并在提交前重新核对是否已取消、暂停或换版。提醒按委托及条件实例去重，回信按委托版本去重，归档按回信去重。交付使用可恢复的同事务写入，或持久待交付状态和数据库唯一键；允许模型重试，用户只收到同一稳定结果一次。
- 观察证据来自 `observations.query` 和 W05 基线，以设备绑定和主体权限隔离。回信归档复用 W04，带回信 ID、源窗口及版本。轨迹保留原因、覆盖与版本，服务端降级回信不伪造结论。
- 会话新增后台结果时，复用 Agent WS 与按需 HTTP 回读，让 App 关闭期间入库的提醒与回信可在重开后恢复。内容块提供可理解的旧客户端降级。业务调度在 worker 开启时运行，测试与隔离实例可关闭，并可在开启模式注入测试时钟。

## 4. 验收标准

| 场景 | 验收判据与证据 |
| --- | --- |
| W08-A1 确认与计划版本 | 模型提出三类计划。未确认无 worker 作业。改计划再确认只生成所选版本，重复决定不多建。跨账号访问与后台变更被拒。保留 API 返回、任务和轨迹 ID。 |
| W08-A2 暂停、恢复、取消和续期 | 暂停窗口无覆盖计入、截止不变。恢复只继续剩余窗口。取消后在途检查结果不投递。续期需确认，旧回信保留可查。聊天与委托簿入口分别测。 |
| W08-A3 关闭 App、服务重启 | 关闭 App 后观察继续。至少覆盖作业领取后及交付前重启，在固定时钟下最终回信和归档各一条。重开 App 可在原主题定位；WS 重连与 HTTP 补读不产生重复。 |
| W08-A4 三类委托与数据缺口 | 事实阈值触发一次提醒，完整窗口到期回信。就绪数值比较引用精确 W05 版本，未就绪两种方案与当天覆盖不足分别验证。定时回顾有数据与无数据均到期交付。 |
| W08-A5 失败降级 | 模型超时、格式不合法及重试耗尽后仅有一封降级回信，明确覆盖、缺口和未知，长期记忆无伪事实。测试 R1 自治工具权限与 W01–W07 回归。 |
| W08-A6 iOS 模拟器 | Expo SDK 58 实际 bundle 内完成卡片编辑、拒绝／确认、委托簿操作、关闭与重开、回信来源下钻。验收记录须注明提交、账号环境、数据窗口、WS/HTTP、任务与轨迹标识。写入及重启用隔离同名账号，统计证据优先使用授权只读观测副本。 |

## 5. 交付顺序

先落地 worker、数据库迁移、检查点与消息的持久边界，供 W09 引用。随后接入委托工具、确认、UI 和验收。新增行为评测先与 W09/W10 预留编号，禁止复用 E1–E41。上线前联检 Alembic 单 head、旧版本兼容、真实 MiniMax 跨包行为回归与客户端完整门槛。实现和验收完成后在本节追加提交、记录与边界。
