# P07 对话补资料、确认与纠正

状态：2026-11-22 讨论稿，等待项目负责人澄清决策。spec 定稿后开始实现。

依据：[Agent 产品集成设计 §6.7](./agent-product-integration-design.md)、[P00 最小契约 §4](./agent-p00-contract.md)、[P07 工作包](./agent-implementation-work-packages.md)。

## 目标与前置

主人在伙伴页补充或纠正当前宠物的资料。明确且无歧义的保存指令在服务端成功写入后得到回显。普通陈述可在对话内确认、修改或略过。返回宠物档案可以看到更新，之后向宠物或照料助手提问时，两位角色都使用同一份已确认资料。

本稿根据远端 `main` 的 `0010f5a` 核对。P02 的回合存储、P05 的意图路由、P06 的伙伴容器已在该基线上可用，G1 的生产验收由原会话收尾。P07 开始实现前重新核对 G1 最新提交及相关回合接口。项目负责人定产品决策，本包负责宠物资料和对话确认闭环。P08 负责角色设定，P09 消费已确认事实与经历并负责长期检索及汇总。

## 资料边界与时间

| 内容 | 规范化与展示 | 修订语义 |
| --- | --- | --- |
| 生日 | 已知的完整日历日期，档案显示日期及按当天计算的年龄。缺年、月或日时保留原话并请求补充 | 替换当前值，保留历史值、来源和修订关系 |
| 约略年龄 | 保存主人描述的年龄、精度和陈述日期。展示“截至该日，主人估计约……” | 保留各次陈述，明确纠正时将目标版本标记为已修订。只知道年龄时保持生日为空 |
| 体重 | 保存测量日期和公斤值，保留原始数字和单位。“今天称了九斤”按消息日期记录 4.5 kg | 当天可有多次测量，明确选中某条体重时可纠正。档案的最新体重按测量日期排序，同日按记录顺序排列 |
| 主人讲述的日常经历 | 只接收属于当前宠物的具体经历，例如散步、去公园。保留主人原话及可确定的发生日期或范围。发生日期缺失时标明未知 | 保留来源与确认状态，交给 P09 消费 |

以消息接收时的上海日期解析“今天”“昨天”，确认跨日时仍用原消息日期。测量日期未知时先澄清，“帮我记一下 4.5 公斤”不能自动补成今天称重。生日和测量日期分别做合法日历及非未来校验。保留接收、确认、保存时间，体验中使用实际发生时间。

首版只处理主人表达的当前宠物事实或经历。假设、引用其他宠物、否定但未提供纠正值、无法判明主体的内容保持原意。模糊年龄可以按原精度确认，互斥值和无法解析的重量单位先澄清。长期偏好、医疗资料、助手设定、观测更正、搜索和后台委托超出本包范围。

## 用户流程

1. 在伙伴页发消息。已有范围和角色路由继续工作。服务端从相关主人消息识别允许的候选，校验宠物归属、主体、值、时间和保存意图。角色文本可引用未确认陈述时保留“你提到”的来源与不确定性。
2. 普通陈述可在原回合下显示一张可忽略的确认卡，卡片列出字段、日期、候选值和冲突时的当前值。同一消息的多条候选可合并展示，主人可逐项确认、修改或略过。确认卡继续随历史回合显示，保存状态不依赖 App 草稿。
3. 对明确且有效的保存指令，或主人操作确认后，服务端事务提交，再显示“已保存”及实际存入的值。失败显示可重试或修正的反馈，保留主人原话和已存在的候选。
4. 由伙伴页进入现有宠物档案可查看已保存的资料，并通过原档案编辑流程更正。来源详情区分聊天与档案编辑。回到伙伴时还原主题、草稿和滚动位置。历史回合保留当时的结果，已被更正时可跳到当前值。
5. 下一轮伙伴回答由服务端载入宠物档案的最新确认版本。宠物和照料助手的角色选择只影响回答方式。当前档案值及状态优先于历史聊天中的旧候选和旧值。

## 服务端与客户端契约

- 继续使用 `pets` 域维护结构化档案。扩展现有鉴权档案读写与服务端字段校验，由 Agent 确认流程和档案编辑复用同一写入服务。将生日、年龄证据、体重记录与来源修订放在所属业务模型中，旧档案缺项保持为空。新增资料只随主人授权的接口返回。
- 确认提案附着到原 `AgentTurn`，采用可选、向后兼容的结构化字段。每项记录稳定标识、宠物及来源回合、字段、规范化值、原始表达、日期、确认状态和版本。处理确认、修改和略过时校验账号、宠物和提案版本。提交返回实际保存值和记录标识。
- 模型负责识别候选，服务端负责决定能否保存。校验仅允许本包字段。明确保存与卡片确认统一经过服务端写入边界，候选与持久结果关联原回合。主人日常经历保留与 P09 兼容的主体、发生时间、来源和确认状态。
- App 扩展现有 Agent 服务和宠物档案表单，保存后沿用按用户作用域的 `notifyPetChanged`／`usePetChanges` 刷新。回合返回内容新增字段时兼容旧客户端，缺字段时兼容旧后端。聊天确认入口随服务器端能力启用。

## 失败、重试与并发

- 回合重试沿用已有请求去重。确认请求绑定提案版本和动作标识，重复点击、断线重发或服务重启后读取同一持久结果。历史中保留的卡片可继续读取最终状态。
- 资料、来源、修订与确认结果在同一写入事务提交。用户恰在档案页或另一端更新了同一值时，过期提案刷新当前值并再次核对，避免用陈旧提案直接覆盖新资料。
- 识别失败时仍保留主人原话，回复可以正常继续。业务写入失败时回显失败或待重试，避免显示未经提交的“已保存”。已拒绝或已完成的提案不能通过旧请求重新执行。
- 新资料迁移兼容既有账号和历史消息。提案和来源详情按当前宠物权限访问，猜测标识无法读取其他账号内容。模型回复、其他人的宠物陈述、遥测和外部知识均不能发起资料修改。

## 验收与交付

| 场景 | 预期结果 |
| --- | --- |
| 首次明确保存生日、已有生日的明确纠正 | 档案显示相同的新值，来源可追溯。纠正按已确认的冲突规则显示旧值 |
| 刚满三岁、约三岁，以及后来补充生日 | 保留表达精度和日期。只有年龄时生日留空。两者冲突按已确认规则展示 |
| “今天称了九斤，帮我记一下” | 记录消息当日的 4.5 kg，并保留原始单位。当天再次称重时追加，修订仅作用于指定记录 |
| 普通陈述、多候选、修改、略过 | 卡片不阻断聊天。修改后按实际确认值保存，略过不改变档案。退出重进仍可查看状态 |
| 朋友的狗、假设、否定、无从确定主体或称重日期 | 没有错误的写入，必要时提出具体澄清 |
| 宠物档案与两位角色 | 重新读取或重进后都采用最新确认值。旧消息保留，修订可查 |

| 主人讲述一段日常经历 | 可确认及查看来源。P09 可读取已确认的经历，完整检索另按 P09 验收 |
