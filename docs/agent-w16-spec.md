# W16 多会话：伙伴页改为可新建、彼此独立的会话

状态：定稿。2026-11-24 按本地 main（c284e04）核对代码与文档并写成草案，2026-11-25 负责人确认决策后定稿。按本稿实施，验收结论回写在第 9 节之后新增的「验收记录」里。

## 1. 目标与范围

把伙伴页从「每只宠物一条消息流 + 主题聚焦」改成多会话：主人可以新建多个会话，各自独立；一轮对话只带**当前会话**的历史；换话题就新开一个会话。会话列表放在一个左侧抽屉里，不单独占一个页面。

三方群聊形态（主人、爱宠、照料助手）、流式、确认卡、委托、联网来源、图片都保留。变化只在三件事：对话怎么分组、上下文取多宽、主动消息落在哪。

一句话原则：**会话隔离的是对话历史；长期记忆、个人基线、学习进度、氛围快照仍按宠物共享**。新会话里助手仍然认识这只宠物，只是不知道别的会话里聊过什么。

不在本包范围：

- 会话搜索、置顶、归档、模型生成标题。
- 长期记忆按会话隔离。
- 会话内长历史摘要。会话内仍取最近 12 个已完成回合作为模型历史，与现在一致，更早的内容靠长期记忆。
- 边缘滑动打开抽屉，原因见 6.2。

## 2. 已确认的决策（2026-11-25）

| 决策 | 结论 |
| --- | --- |
| D1 列表入口 | 左侧抽屉。做成伙伴页内的浮层组件，不用导航层的抽屉，不新增路由 |
| D2 主动消息归属 | 各自成一个系统会话：设备告警、学习完成每个主题一个会话；周期回顾每条汇总一个会话；委托回信回到确认它的会话 |
| D3 存量迁移 | 每只宠物建一个「历史聊天」会话，全部旧回合归入其中，不按旧主题拆分 |
| D4 旧客户端 | 不保留兼容，直接升级。`conversationId` 从此必填 |
| D5 标题 | 取首条主人消息前 20 字，可手动改名；系统会话用主题标题 |
| D6 删除 | 软删除；会话里有进行中的委托或未结束的关怀主题时拒绝删除并提示 |
| D7 记忆范围 | 长期记忆跨会话共享 |
| D8 发布 | 一次合入。CI 里 OTA 发布任务依赖部署任务成功，先后顺序有保证 |

没有采用的方案，备查：

- 导航层抽屉（`expo-router/drawer`，已随 expo-router 58.0.27 安装）：要在伙伴标签内再嵌一层导航布局并加手势根视图，与 NativeTabs 的配合没有验证过。按按钮打开用不到它提供的手势和返回栈。
- 按旧主题拆分存量：旧 `topic_id` 一列混用了回合 id 和关怀主题 id，无法可靠区分，拆错不可逆。
- 全部主动消息进一个固定会话：追问会带上无关的旧提醒。
- 模型生成标题：每个会话多一次模型调用，需要异步作业。

升级窗口（D4 的直接后果）：从服务端部署完成到用户装上新包之间，旧版包发消息会得到 400，读历史会失败，界面显示现有的可重试提示，装上新包即恢复。窗口长度约等于 CI 里部署到 OTA 发布的间隔。

## 3. 现状与依赖面（2026-11-24 核对）

服务端：

- 数据：`agent_turns` 只有 `pet_id`、`topic_id`、`reply_to`，没有会话实体。`topic_id` 一列两种含义：对话路径存话题根回合的 id，后台交付存关怀主题 `agent_care_topics.id`。
- 历史：`routes.history_rows` 是唯一按话题取历史的地方。调用点是 `routes.turns` 的同步路径和 `group._context`，路由器的 `group.topic_lines` 也用它。模型每轮看最近 12 个已完成回合（`loop.HISTORY_TURNS`），路由器看最近 3 轮（`router.TOPIC_TURNS`）。
- 写 `topic_id` 的三处：对话 POST（`routes.py:274`）、关怀事件交付（`care_jobs.py:635`）、委托回信交付（`tasks.py:804`）。周期回顾的汇总消息不带 `topic_id`（`care_jobs.py:549`），一条消息可以涉及多个发现主题。
- 列表：`GET turns` 按宠物取全部回合，每页 40。没有会话级的未读计数，只有回合上的 `read_at`。
- 深链：`inbox.resolve_target` 产出 `/agent?inboxId=&topicId=&turnId=` 或 `?inboxId=&deliveryId=&taskId=&turnId=`。委托簿用 `tasks.public()` 里的 `topicId` 回原会话。
- 迁移：单 head `0022`。

客户端：

- `stores/agent-chat.ts` 是模块级单例：一个 `turns` 数组加一个 `topic` 过滤值。`hooks/use-agent-chat.ts` 管生命周期和 AsyncStorage 快照。
- 伙伴页之外只有三处依赖聊天 store：`agent-tasks.tsx:156`（`setTopic` 后 `router.back()`）、`proposal-card.tsx` 与 `task-proposal-card.tsx`（`applyTurn`）。今日页、收件箱页、`_layout.tsx` 不碰它。
- 进伙伴页的带参导航只有一条：`inbox/[id].tsx:55` 的 `router.replace('/agent?…')`。
- 「主题聚焦」相关界面有三处：顶部「正在说这件事」横幅、消息下的「继续聊这件事」、输入区占位符「继续说这件事…」。
- 导航与浮层：伙伴页在 `NativeTabs` 里，底部是原生悬浮标签栏。App 里现有的浮层（通知中心、图片查看器、评论面板等）都是 RN `Modal`；通知中心的验收截图显示它盖得住标签栏。App 没有导航抽屉，没有手势根视图，也没有用过 `BackHandler`。

已知的旧问题：从关怀卡追问时，客户端把关怀主题 id 当 `topicId` 发出，服务端却按回合 id 解析，话题会挂到一个无关的回合上，无关对话因此进入后续追问的模型历史（2026-11-24 隔离库复现，模型打桩）。本包去掉 `topicId` 之后这个问题不再存在。

## 4. 数据模型与迁移（alembic `0023`）

新表 `agent_conversations`，模型 `AgentConversation`：

| 列 | 说明 |
| --- | --- |
| `id` | 主键 |
| `pet_id` | 归属宠物，索引 |
| `kind` | `chat` 主人会话，`care` 系统会话 |
| `care_kind` | 系统会话细分：`device`、`learning`、`review`；主人会话为空 |
| `title` | 标题，不超过 80 字符 |
| `title_custom` | 1 表示主人改过名，之后不再自动更新 |
| `created_at`、`updated_at`、`last_turn_at` | 均带时区；`last_turn_at` 是最后一条回合的时间，列表按它排序 |
| `deleted_at` | 软删除 |

加列：

- `agent_turns.conversation_id`，建索引。列定义保持可空，是为了不在 SQLite 上重建这张最大的 Agent 表；迁移结束时所有行都有值，之后由代码保证必填。
- `agent_care_topics.conversation_id`，可空，唯一。设备和学习类主题首次交付时回填。
- `agent_tasks.conversation_id`，可空。委托确认时取确认回合所在的会话。

不再读写的旧列：`agent_turns.topic_id` 和 `agent_tasks.topic_id` 留在库里，本包不删，也不再写入和读取。

迁移步骤：

1. 建表、加列、建索引。
2. 每只名下有回合的宠物建一行「历史聊天」（`kind=chat`，时间取最早和最晚的回合），把该宠物的全部回合指向它。
3. 该宠物的现有委托指向同一行。
4. 关怀主题不动，首次交付时再建会话。
5. 断言没有 `conversation_id` 为空的回合，不满足就让迁移失败。

空库（测试和新装）上第 2 到 5 步没有行要处理。降级时删表、删列。

不变量，由代码保证：

- 新发出的回合和后台交付的回合都有 `conversation_id`。
- 同一宠物的主人会话里，没有回合的至多一个（见 5.2 的新建规则）。

## 5. 服务端设计

### 5.1 模块

- 新增 `agent/conversations.py`：会话的建立、标题、序列化、未读与预览、历史查询、删除前检查。
- 新增 `agent/conversation_routes.py`，独立 blueprint，前缀 `/api/app/agent`，注册方式同 `inbox_routes`。
- 改动：`routes.py`（turns）、`group.py`（历史与推帧）、`deliver.py`、`care_jobs.py`、`tasks.py`、`inbox.py` 与 `inbox_routes.py`、`ws.py`、`db/models/agent.py`。

### 5.2 接口

| 方法与路径 | 作用 | 要点 |
| --- | --- | --- |
| `GET /pets/<pet_id>/conversations` | 会话列表 | 按最近活动倒序，默认 50 条，`offset` 翻页；不含已删除 |
| `POST /pets/<pet_id>/conversations` | 新建会话 | 最近一个仍为空且未改名的主人会话直接复用，避免连点产生一串空会话；响应带 `created` |
| `PATCH /conversations/<id>` | 改名 | 标题去空白后 1 到 40 字；置 `title_custom` |
| `DELETE /conversations/<id>` | 删除 | 软删除；有进行中的委托（观察中、等基线、已暂停）或未结束的关怀主题（open、ongoing）时返回 409 并带数量 |
| `POST /conversations/<id>/read` | 标已读 | 不带 `ids` 标该会话全部未读，带 `ids` 只标这些；返回会话摘要与被标的回合。取代现在的 `POST /pets/<id>/read` |
| `GET /pets/<pet_id>/turns` | 取某个会话的历史 | `conversationId` 必填，缺失返回 400，不属于本人或已删除返回 404；每页 40 |
| `POST /pets/<pet_id>/turns` | 发消息 | `conversationId` 必填；`replyTo` 必须在同一个会话；不再接受 `topicId` |

会话摘要字段：`id`、`petId`、`kind`、`careKind`、`title`、`titleCustom`、`createdAt`、`updatedAt`、`lastTurnAt`、`turnCount`、`unread`、`preview{text, at}`。预览取最后一条回合的主人原话，没有则取首段正文，截 40 字。

标题规则：

- 主人会话在第一条主人消息受理时取原话前 20 字，纯图片消息用「图片消息」。
- 设备和学习类系统会话取关怀主题的标题；主题改了标题而主人没改过名时跟随。
- 回顾会话由服务端按窗口生成，沿用现有的上海时区口径（`care.SHANGHAI`）：「观察小结 · 11月24日」「本周回顾 · 11/17–11/23」。

未读的定义：会话内 `read_at` 为空且状态不是 pending 的回合数。它与收件箱的已读是两套状态，沿用现状，不合并。

### 5.3 历史只取当前会话

- 新增 `conversations.history(session, pet, before_turn_id, conversation_id, limit)`：同一会话内、该回合之前、已完成的回合。它取代 `routes.history_rows`，旧函数删除；`routes.turns` 的同步路径、`group._context` 和 `group.topic_lines` 都改用它，路由器看的是当前会话最近 3 轮。`loop.py` 不变。
- 回合快照里的 `topicId` 换成 `conversationId`。`inbox.turn_public` 是 `routes.public` 的一份拷贝，合并成一个实现。
- 设备和学习类关怀会话：上下文里加一行由服务端确定性生成的提示，形如「本会话来自主动提醒：主题 #12『项圈电量偏低』（进行中）」，模型据此直接查 `read_care_topics`。不新增工具。
- `GET turns` 里对超时 pending 回合的收尾仍按宠物全量扫描，不因只取一个会话而漏掉。

### 5.4 后台消息归属

- 设备告警、学习完成：主题首次交付时建一个 `kind=care` 的会话，并回填 `agent_care_topics.conversation_id`。之后的升级、恢复消息进同一个会话。
- 周期回顾：每条汇总各建一个 `care_kind=review` 的会话。它可能涉及多个主题，不与单个主题绑定。
- 委托提醒与回信：进确认该委托的会话，即 `agent_tasks.conversation_id`。
- `deliver_background_message` 去掉 `topic_id` 参数，`conversation_id` 必填，写入后更新会话的 `last_turn_at`。
- 迁移前就开着、在「历史聊天」里发过消息的关怀主题：后续的升级和恢复消息进它新建的会话，旧消息不搬。
- 从没发布过消息的安静主题没有会话：从收件箱打开时沿用现状，在当前会话上方展示「来自收件箱」的主题卡。

### 5.5 WebSocket

- `turn`、`delta`、`message_delta`、`message`、`message_status` 五种帧都带 `conversationId`，取自回合行。
- 新增 `conversation` 帧，内容是会话摘要。后台交付落进新会话或更新了会话之后，在 `push_delivered` 里推给该用户的全部连接，客户端据此更新列表，不必整表重拉。
- 连接、鉴权、心跳方式不变。

### 5.6 收件箱与深链

- `inbox.resolve_target` 的参数：`inboxId`；`conversationId`，即锚点回合所在的会话；`turnId`。关怀类另带 `topicId`，回信类另带 `deliveryId` 和 `taskId`。
- 锚点回合所在的会话已删除时不给 `conversationId`。关怀类沿用安静主题的做法，在当前会话上方展示主题卡；回信类标记为来源不可用。
- `GET /agent/inbox/turn/<id>` 返回的回合带 `conversationId`；会话已删除时返回 404。
- 委托簿：`tasks.public(task)` 用 `conversationId` 和 `conversationDeleted` 取代 `topicId`。

### 5.7 删除的边界

- 删除后：不出现在列表；`GET` 和 `POST turns` 对它都返回 404；收件箱按 5.6 处理；委托簿不显示「回到原会话」。
- 不删除任何回合、轨迹和记忆，审计与回放需要它们。

## 6. 客户端设计

### 6.1 信息架构与导航

- 伙伴页一次显示一个会话。URL 参数 `conversationId` 是当前会话；`turnId`、`deliveryId`、`taskId`、`topicId`、`inboxId` 用于定位和标已读。
- 抽屉是伙伴页内的浮层组件，不是路由。
- 落地规则：带 `conversationId` 就打开它；不带时打开本机记住的上次会话；没有就取列表第一个；列表为空时自动建一个。列表加载完成后总有当前会话。
- 当前会话的真值在 store。URL 参数出现或变化时打开它；在抽屉里切换会话时用 `router.setParams` 把 `conversationId` 写回，两者保持一致。W12 的 `inbox/[id].tsx` 已经用 `router.replace` 跳到带参数的 `/agent`，是同一机制的先例。
- 切换会话只换列表区，按会话 id 重新挂载；页头、输入区容器和键盘协调不重建。

### 6.2 抽屉

交互：

- 入口是页头左侧的「会话列表」按钮，取代爪印头像。任一会话有未读时，按钮上显示一个小圆点。
- 打开：面板从左侧滑入，遮罩淡入并压暗其余区域，盖住底部原生标签栏。打开前先收起键盘。
- 关闭：点遮罩、点右上角的关闭按钮、选中一个会话、按 Android 返回键、页面失焦。
- 面板自上而下是页头、新对话、列表。页头左侧是「对话」，右侧是「新对话」和关闭按钮；关闭按钮与通知中心用同一个图标。
- 宽度：手机上取屏幕宽度的 82%，不超过 360；平板上固定 360。面板全高，顶部留安全区，底部留 Home 指示条的高度。
- 列表按最近活动倒序。每行是类型图标、标题、带时间的预览、未读圆点，行尾有「⋯」。当前会话的行用品牌浅底标出。系统会话的类型图标区分设备提醒、学习完成、周期回顾，主人会话用会话图标。图标名称需通过类型检查。
- 「新对话」：请求成功后关闭抽屉并切到新会话；失败在抽屉内显示可以重试的错误。
- 「⋯」打开底部动作面板，提供重命名和删除，删除用危险色。重命名是居中的文字输入弹窗，删除是确认弹窗。返回 409 时展示服务端给的原因，有进行中的委托时附「去委托簿」。这几层都画在同一个浮层里，不叠加第二个系统弹窗。
- 删除的是当前会话时，切到列表里的下一个；没有其他会话就自动建一个。
- 每次打开抽屉拉一次列表，有缓存先显示缓存；收到 `conversation` 帧时原地更新。
- 状态：读取中、失败重试、空列表。空列表只在新建也失败时出现。

实现方式：

- 用 RN `Modal`（透明）承载，和通知中心、图片查看器是同一做法，这样才能盖住原生标签栏。进出场动画用 Reanimated：打开时系统淡入，叠加面板从左滑入；系统开启「减弱动态效果」时只淡入。
- 关闭时默认用系统的淡出。实测如果淡出与面板动画配合不理想，改成先播完滑出再卸载浮层。
- Android 返回键由 `Modal` 的 `onRequestClose` 承接。
- 组件是 `components/agent/conversation-drawer.tsx`，内部分出会话行和三个动作层（动作面板、重命名、删除确认）。不新增依赖。
- 实施的第一步先做抽屉外壳的 spike：只验证打开和关闭的动画、关闭后聊天列表的滚动位置不变、键盘不闪。确认可用再接数据。
- 退路：如果 `Modal` 在这一页上有问题（滚动位置跳动或键盘闪烁），改成页内覆盖层。打开、关闭、切换会话的行为都不变，只有一点不同：遮罩盖不住原生标签栏，标签栏浮在遮罩上方，仍然可以点。

不做边缘滑动打开：它需要在根部加手势容器，会影响全 App 的触摸处理，需要单独做真机验证。按按钮打开不依赖手势。

伙伴页的其余改动：

- 页头：标题是当前会话的标题，空会话显示「新对话」，单行省略；副标题仍是「你 · 宠物 · 助手」；委托簿和学习进度两个 pill 不变。
- 移除「正在说这件事」横幅。消息下的「继续聊这件事」去掉，失败的回合仍显示「再说一次」。「回复」引用保留。关怀卡的「为什么提醒我？」保留，改为在当前会话里预填问题并引用那张卡。
- 空会话沿用现有的欢迎态和快捷建议。
- 「来自收件箱」锚点卡：锚点回合属于别的会话时，先切到那个会话再定位；会话不可用或没有会话时才在当前会话上方单独展示卡片。
- 伙伴页在前台且抽屉没打开时，当前会话的新回合到达后标为已读。

### 6.3 store 与 Hook

- `stores/agent-chat.ts` 改为按会话分组：`list` 是会话摘要，`activeId` 是当前会话，`chats[id]` 存该会话的回合、草稿、发言对象、引用、附件、发送中状态、待重试请求、错误和滚动位置。`services/agent-chat-turns.ts` 的纯函数不变，只是作用在某个会话的回合数组上。
- 帧路由：按帧里的 `conversationId` 进对应的会话。没有 `conversationId` 的帧丢弃。非当前会话的帧只更新它的缓存和列表摘要，不动界面。
- 内存里最多保留 8 个会话的回合缓存，超出时淘汰最久未打开的。草稿等轻状态不淘汰。
- 新增 `hooks/use-agent-conversations.ts`，管列表的读取、新建、改名、删除，账号标签的写法同 `use-agent-inbox`。`hooks/use-agent-chat.ts` 收窄为只管当前会话的生命周期。
- 发送中、失败回填、同键重试都按会话隔离：在 A 会话发送后立刻切到 B，不影响 B 的输入区；A 的失败回到 A 时才显示。
- 降级轮询：WS 断开时轮询「有未完成回合的会话」和列表。

### 6.4 本地快照与账号隔离

- AsyncStorage 仍按用户一个键，存上次打开的会话，以及最近 5 个会话的草稿、发言对象、引用、滚动位置和最近 20 个回合。本地乐观回合不进快照。
- 账号标签规则不变：列表和各会话缓存都带账号 id，渲染时推导。退出或换账号后立即清空，晚到的旧账号响应按标签丢弃。

### 6.5 联动

- `inbox/[id].tsx`：服务端解析结果里多出的 `conversationId` 原样拼进 URL，不需要改代码。
- `agent-tasks.tsx` 的「回到原会话」：改为带 `conversationId` 跳到伙伴页；会话已删除时不显示这个入口。
- 今日预览、通知中心、推送都经 `/inbox/<id>` 解析，不需要改。

### 6.6 删除的代码

`topic` 过滤与 `setTopic`、请求里的 `topicId`、回合上的 `topicId` 字段、输入区的 `inTopic`、`onContinueTopic`，以及 `inbox-anchor` 里按 `topicId` 匹配回合的分支。参数解析保留，安静主题仍要展示主题卡。

## 7. 失败、降级与幂等

- 新建会话失败：当前会话不受影响，抽屉内显示可以重试的错误。
- 列表读取失败：抽屉内显示重试；伙伴页用本地缓存的会话继续用。
- 切换到一个没加载过的会话失败：只在该会话显示重试，其余会话照常。
- 发送请求键仍按（宠物，`requestId`）去重。同键但不同会话视为另一条消息，返回 409。
- 不带群聊协议声明的同步 POST（阻塞到生成结束）不变；群聊协议的 202 和逐条消息不变。

功能项：

1. 抽屉的打开、关闭、切换、新建、改名、删除；未读圆点与页头按钮上的小圆点。

3. A 会话里说过的事，在新会话追问时模型如实表示这个会话里没聊过。
4. 今日预览、收件箱、通知深链打开后落在正确的会话并定位到那条消息，展示之后才标已读。
5. 委托簿「回到原会话」进确认它的会话；到期回信出现在同一个会话。

8. 「历史聊天」里能看到全部旧消息。
9. 断线重连、轮询恢复、换账号后旧账号的会话立即消失、冷启动深链。
