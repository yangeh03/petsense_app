# W18 取消前置意图路由：按选择派发 + 爱宠越界转交

2026-11-25。实施基线 `main@dd51ffe`（双 Agent 群聊已合入主干）。本包与 ZCode 的 W17（pet-first-handoff）并行、互相独立，两边各自实现。

## 1. 背景与目标

伙伴页（群聊协议 `group-v1`）当前在主人消息与角色回复之间有一次**前置意图路由**：`server/petsense/agent/router.py` 的 `router.route()`——一次不带工具的模型调用，产出 `scope/intent/companion/professional/order/follows`，服务端再把它归一化成「谁发言、领什么任务」的计划。这一步发生在任何正文之前，直接叠加在首字延迟上：

- 陪伴类问题（本来一次调用就够）也要先等路由；
- 专业类问题变成「路由 + 回答」两次串行调用，且分工正确性取决于路由模型的一次判断。

本包**删掉这一步**，改成：派发由主人的选择直接决定；角色边界由两个角色的系统提示词约束；爱宠在默认模式下遇到自己答不了的问题时，用一次工具调用把专业部分转交给照料助手。

目标：

1. 陪伴类与单角色问题：模型调用次数由 2 降到 1，首字延迟只由角色自身那一次调用决定。
2. 专业类问题：调用次数不增（角色调用 + 转交后的助手调用），但少一次固定开销与「路由猜错分工」的可能。
3. 权限不因删路由而放松：范围门从「服务端前置分类」改为「照料助手在它自己那次调用里自报范围」，角色门（爱宠不得查数据、写入、操作）仍由代码执行。

不在本包范围：旧协议单 Agent 链路（`routes.py` 的 legacy 分支）、客户端视觉改版、模型供应商替换、真实项圈硬件验收。

## 3. 派发规则（服务端确定性，无模型调用）

| `target` | 计划（按顺序） | 转交工具 | 说明 |
| --- | --- | --- | --- |
| `auto`（默认） | 爱宠 →（转交时）照料助手 | 挂载 | 爱宠先答；它判断自己答不了时转交，助手在同一回合追加一条 |
| `pet` | 爱宠 | 不挂载 | 只由爱宠回答；遇到专业问题按 D1 措辞如实说不懂 |
| `assistant` | 照料助手 | 不适用 | 只由照料助手回答 |
| `both` | 爱宠 → 照料助手 | 不挂载 | 两位各一条：爱宠接陪伴部分，助手答专业部分 |

派发只依赖主人本轮的选择，不再看消息内容，也不看引用对象。**引用的实际发言人不改变派发**（引用只作为上下文进入角色提示），避免「引用谁就变成谁答」的隐式改派。

消息行（`agent_messages`）的创建时机：

- `auto`：派发时只建爱宠那条（position 0）；照料助手那条在**转交发生后**才建（position 1），因此客户端先看到爱宠的完整回复，再看到助手那条出现。
- `pet` / `assistant`：派发时建一条（position 0）。
- `both`：派发时建两条（position 0/1）。

### 3.1 相对旧路由的行为变化（有意为之）

| 场景 | 旧（前置路由） | 新（按选择派发） |
| --- | --- | --- |
| 未点名 + 纯陪伴 | 路由判定后爱宠答 | 爱宠答（**少一次模型调用**） |
| 未点名 + 专业问题 | 路由判定后照料助手答 | 爱宠先答并转交 → 照料助手答（两条消息，调用次数持平） |
| 未点名 + 混合问题 | 路由拆两段原话分给两位 | 爱宠接陪伴部分并转交 → 照料助手答专业部分（不再逐字拆原话，两位看到完整原话 + 各自任务） |
| 只点爱宠 + 专业问题 | 爱宠承接一句 + 照料助手答 | **只有爱宠答**（说不懂并建议问照料助手，D1） |
| 只点照料助手 | 照料助手答 | 照料助手答（不变） |
| 两位都回 | 路由给两位各自分工 | 两位都回（不变；两位彼此独立，不再有「承接」标记） |
| 纯图片消息（未点名） | 路由看不到图片 → 归照料助手 | **爱宠先答**（它能看到照片；需要数据时转交） |
| 模糊输入（如「然后呢？」） | 路由判定范围未确认 → 一条有限澄清 | 爱宠问一个简短澄清（服务端任务文本明确要求），照料助手被转交时同样澄清 |
| 范围外请求 | 路由判定 `out_of_scope` → 助手不挂工具 | 照料助手在同一次调用里自报 `out_of_scope` → 该轮工具调用被拒，之后的轮次不再挂工具与联网 |

## 4. 转交流程（D2/D3）

1. 默认模式下，爱宠那一次调用的工具 schema 里带 `handoff_to_assistant`；其它模式不带（**工具在不在 schemas 里就是「本轮允不允许转交」的权威**）。
2. 爱宠判断这条消息里需要查证、知识、联网、修改或安排的部分，**先说一句陪伴话**，再调用 `handoff_to_assistant`（参数 `reason`：一句话说明哪部分需要接手，≤60 字）。
3. 服务端执行该工具：校验角色（只有爱宠能调）与本轮是否允许转交，通过后返回结构化结果 `{'handoff': True, 'assistant': '照料助手会在本轮接着回答'}`，并把该次运行标记为「已转交」。
4. **爱宠这一轮随即收尾**：不再追问模型（省一次调用）。宠物消息正文 = 本轮已产出的文本；本轮没有文本时用服务端兜底承接句「我陪着你，这件事让照料助手帮你看看。」。
5. 爱宠消息落终态后，服务端创建照料助手那条消息（position 1）并推帧，随后运行照料助手。照料助手的上下文里带一条服务端补充：爱宠刚发的原话 + 「专业部分交给你，不要重复它的话」。
6. 照料助手答完，本回合收尾。两条消息独立状态：爱宠成功、助手失败时只有助手那条可重试。

转交后照料助手那条的形态与 `both` 模式一致（它拿到的工具、权限、预算与 `both` 里的照料助手相同），差别只在任务文本与上下文补充。

## 5. 角色提示与工具权限

### 5.1 爱宠（`loop._PET_SYSTEM_PROMPT` + 任务文本）

按模式追加一段服务端生成的「本轮任务」：

- **默认（auto）**：「主人没有点名谁，由你先回应。消息里能陪伴的部分你接住；需要查证数据、养宠知识、联网核实、修改保存或持续安排的部分你答不了：先用一句话告诉主人你把这件事交给照料助手，再调用 `handoff_to_assistant` 转交（一次就够）。转交后不要自己回答专业内容。」
- **只选爱宠**：「主人点名了你。你只接陪伴部分；如果这条消息要查证、知识或操作，你不会也不编造：简短说明你不懂并建议主人去问照料助手。本轮没有照料助手发言，不要调用转交。」
- **两位都回**：「主人要两位都回。你只接陪伴部分（至多两句）；需要查证、知识或操作的部分由照料助手另发一条，你不展开，也不要调用转交。」

爱宠的工具集合不变（`read_pet_profile`、`search_memories`），转交工具按模式追加。爱宠的快照仍是 `profile/memory/now` 三节，不给设备与学习数据——**爱宠看不到观测数据本身**，这是「宠物不报数据」的第一道防线。

### 5.2 照料助手（`loop._GROUP_ASSISTANT_HEAD` + 任务文本）

- 群聊提示恢复**范围声明首行**（D4）：`{"scope":"allowed|out_of_scope","intent":"read|social|knowledge|search|write|observe"}`。这一行只给服务端看：流式过滤器（`RoleDeltaFilter`）与终态解析（`parse_stance`）都会剥离它，主人看不到。声明 `out_of_scope` 时服务端拒绝该轮的工具调用并摘除联网搜索。
- 任务文本按模式生成：
  - **被转交**：「爱宠已经把需要查证、知识或操作的部分交给你：回答那部分。结论只来自本次工具结果；不要重复爱宠的话，也不要替它表达感受。」
  - **两位都回**：「只回答主人明确请求的专业部分。爱宠负责陪伴表达，你不替它说话、不复述或评价它的感受；陪伴话语里的动作不是另一个求助。」
  - **只选照料助手**：「回答主人这条消息：需要数据时现场查询，结论只来自本次工具结果；第一句先给结论。」

### 5.3 权限矩阵（代码层，不只靠提示词）

- `handoff_to_assistant` 属于新工具组 `handoff`，只在 `dialogue` 形态、且**爱宠角色 + 本轮允许转交**时挂载；照料助手调用它按越权拒绝（`role_not_allowed`）。
- 范围门：照料助手的 scope 由它自报，`out_of_scope` 时业务与联网工具全部不可用（P00 §3 语义不变，只是判定来源从前置路由换成同一次调用里的声明）。
- 爱宠的范围固定 allowed：它能调用的只有 `read_pet_profile` 与 `search_memories`，写入、观测、联网、动作工具全部按角色门拒绝。

## 6. 持久化与协议

- **不新增迁移**。`agent_routes` 行的语义从「路由结果」改为「派发记录」：`plan_json` 是派发计划，`source='target'`，`scope/intent` 初始 `unknown`，照料助手自报后回填（回放与取证仍能看到当时的范围）。
- `agent_messages.kind`：爱宠正常回复 `respond`、转交 `handoff`、照料助手 `answer`。转交状态落库，进程重启后仍能恢复「助手那条还要跑」。
- **客户端协议形状不变**：回合快照仍带 `messages`，WS 仍推 `message` / `message_delta` / `message_status`。差别只有一点——助手那条消息在转交后才出现。客户端按消息 id 合并（`applyMessageToTurns`），后到的消息直接追加，无需改动渲染。

## 7. 实施步骤

1. `server/petsense/agent/router.py`：删除。`group.py` 的 `_route_stage` 改为 `_dispatch_stage`（确定性派发，无模型调用）；新增 `_handoff_stage`（幂等：转交后建助手消息行）。
2. `server/petsense/agent/registry.py`：注册 `handoff_to_assistant`（新组 `handoff`）；`schemas_for` 增加「本轮是否允许转交」参数；`execute_tool` 增加转交工具的角色门与开关门。
3. `server/petsense/agent/loop.py`：爱宠提示与任务文本按模式拼接；照料助手提示恢复范围声明首行；`run_dialogue` 在角色模式下采纳模型自报 scope 做门控（说话人仍由服务端固定）；爱宠调用转交工具后本轮立即收尾并返回 `handoff` 标记。
4. `server/petsense/agent/group.py`：编排改为「派发 → 逐条生成 → （转交）追加助手 → 收尾」；`_context` 按模式给任务文本；`_finalize` 与重试路径兼容转交状态。
5. 测试：`server/tests/group_testkit.py`（模型桩按种类识别，去掉 router 一类）、`test_agent_group*.py`、夹具 `fixtures/group_fixture_server.py`。
6. 文档：本 spec、`docs/agent-dual-agent-chat-design.md`（标注 §3.2 路由已被本包取代）、`docs/agent-p00-contract.md` §3、`AGENTS.md` 项目记忆。

## 8. 验收标准

| 场景 | 验收判据与证据 |
| --- | --- |
| W18-A1 无路由调用 | 任意目标下服务端不再发起「不带工具的路由调用」；轨迹里没有 `form='route'`；模型调用次数：陪伴 1 次、专业 1 次（爱宠）+ 1 次（照料助手）。 |
| W18-A2 四种派发 | `auto`/`pet`/`assistant`/`both` 各发一条，断言 `messages` 的角色、条数与顺序：auto 陪伴 1 条、auto 专业 2 条（爱宠 + 照料助手）、pet 1 条、assistant 1 条、both 2 条。 |
| W18-A3 默认模式转交 | 爱宠调用 `handoff_to_assistant` 后：爱宠消息先完成（含它自己那句），照料助手消息随后出现并回答专业部分；两段文本不重复；助手那条带工具调用与来源。 |
| W18-A4 只选爱宠遇专业问题 | 本轮只有爱宠一条消息，正文是「不懂 + 建议问照料助手」，没有事实数值，没有 `handoff_to_assistant` 调用（该模式不挂此工具）。 |
| W18-A5 两位都回 | 两条消息互补：爱宠不报数据、不替助手作答；助手只答专业部分。 |
| W18-A6 范围门未放松 | 范围外请求（如编程）里照料助手的工具调用被拒（`scope_not_allowed`），自报 `out_of_scope` 之后的轮次不再挂工具与联网；爱宠任何时候都没有观测与联网工具。 |
| W18-A7 失败与重试 | 爱宠成功、照料助手失败时只有助手那条可重试；爱宠消息不重复。重试沿用同一份派发记录，不重新派发；转交后助手那条失败再重试，仍沿用转交状态。 |
| W18-A8 恢复 | 服务重启后：转交已发生但助手未跑完的回合能继续跑完；未开始的回合按派发记录继续。 |
| W18-A9 兼容 | 旧协议客户端读到的回合结构不变（镜像含两位标记）；`PETSENSE_DUAL_AGENT_ENABLED=0` 时新消息走旧路径。 |
| W18-A10 延迟对照 | 同一组样本对照旧链路：首条正文首字时间、整轮完成时间、模型调用次数三项都记录（旧链路数据取本包实施前的基线）。 |
| W18-A11 回归 | 服务端 `python -m unittest discover -s server/tests` 全绿；客户端 `npm run lint` / `typecheck` / `format:check` / `npm test` 全绿。 |
| W18-A12 iOS 模拟器 | 真实 bundle 内走查四条路径：默认陪伴、默认专业（转交）、只选爱宠问专业、两位都回。**功能项**：气泡条数与身份、助手那条的来源卡、失败与重试、引用与断线重连。**视觉走查项**：浅色/深色下两条气泡的对齐与间距、转交后等待态的呈现、转交那一句的换行与截断、与既有伙伴页设计语言一致。 |

## 9. 风险与回退

| 风险 | 处置 |
| --- | --- |
| 爱宠误判范围：该转交时不转交（专业问题被当成陪伴回答） | 提示词约束 + 爱宠没有观测工具（拿不到数据）+ 行为评测固定样本；后续可加确定性护栏（正文出现数据型数值时替换为承接句） |
| 爱宠乱转交：能答的问题也转交 | 转交工具只在默认模式挂载；转交后照料助手必然回答，专业问题不会没人接；代价是多一次调用 |
| 照料助手自报范围不可靠（该拒的没拒） | 与 legacy 单 Agent 同源风险，权限矩阵仍在代码层；自报 `out_of_scope` 后工具一律被拒（宽松方向是「多给了工具」，不是「越权」） |
| 转交后进程重启 | 转交状态落在 `agent_messages.kind='handoff'`，`_handoff_stage` 幂等，重启后继续 |
| 回归风险：群聊协议形状变化 | 客户端协议不变；旧协议镜像路径不变；`PETSENSE_DUAL_AGENT_ENABLED=0` 可全局回退 |
