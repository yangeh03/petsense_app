# Dashboard 声音展示修正

用户指出声音提示不可见、片段计数缺少意义，并要求保持文案精简。复核：PetHero 的声音区域以 current 为渲染条件（10秒新鲜度），离线后消失；片段总数受合并阈值、采集覆盖、模型抖动影响，没有常态基线，不支持吠叫次数或异常结论；每个零时长识别单独展示“短片段”缺少产品价值。

保留中央动作动画。声音行始终存在：有效当前声音为“安静/正在吠叫/正在嚎叫/疑似呜咽”；准备中、未识别、未连接、未更新分别表达，不把离线等于安静。声音行可进入已有诊断页；只有有效声音使用强调色。当前结果不人为延长，历史事件承担回看。

今日记录只显示走动、静止时长与实际覆盖，不再显示片段计数。独立“声音记录”卡呈现今日何时听到了什么，默认最近3条，按需更多。相邻声音记录间隔不超过30秒时在展示层合并成同一条（可以含不同声音），只表达该时间范围内听到过什么，不推断连续发声时长。呜咽使用“疑似”而不加长说明。展开单条只显示记录时间范围，不显示模型置信度；不提供不存在的录音按钮。没有声音事件时统一显示“暂无声音记录”。通用遥测覆盖不能证明声音模型已有效工作，不以走动/体征采集推断全天没有吠叫。仅查看现有API返回的最近记录，不冒称完整历史。

方案：将提示保持在线可见不能解决断流不可发现；将总数换成时长也缺乏采样完整性；选择持久的状态入口和有时间的声音记录。后台继续保存原始片段和兼容字段，不改变数据库、固件或虚构新指标。之前分支尚未部署，用户线上界面也不一定含这些改动。

验收：所有连接/声音状态、quiet置信度0、低置信度、断流、间隔合并和乱序输入行为测试；本地computer use确认离线也有声音行、首页不含片段数。真实四声音实机和误报率不作已验证声明。
