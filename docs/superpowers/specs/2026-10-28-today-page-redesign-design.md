# 今日页面重设计

日期：2026-10-28。代码基线：main `2231ab1`（今日页与 worktree `location-walk-next` 完全一致）。

状态：已确认并实现（2026-10-28 同日）。用户决策：状态条采用胶囊并排（方案 A）；声音次数摘要不进今日页，保留在记录页；走动/静止的动作识别精度优化单独立项，不在本次范围。文中示例数值取自 Marni 2026-10-28 的真实聚合数据，实时值为示意。

## 1. 用户问题与诊断

用户对今日页的三条反馈，逐条核对了代码与生产数据（账号 petsense / 宠物 Marni，2026-10-28）：

### 1.1 "健康体征单调、数值类目少"

现状：卡片只有心率 / 血氧 / 传感器温度三个瞬时值，来自最新一帧；当天均值和区间服务端已经算好（`/api/app/observations` 的 `metrics`）但页面完全没用。遥测帧里 `TelemetryHealth` 共 12 个字段，实际可靠的只有 3 个体征 + 环境温度；HRV、血压、呼吸、微循环、疲劳在真实设备帧里全部为 0（固件未填充），不能上界面。

另一个被掩盖的问题：最新帧经常出现 `valid: true` 但六个数值全为 0（项圈在发帧、传感器没贴合），页面显示三个裸 "—"，用户不知道是坏了、没数据还是该做什么。本次评审时 Marni 项圈在线，体征区就是全 "—"。

### 1.2 "走动/静止怎么算的？感觉不准"

计算规则（`server/petsense/telemetry/observations.py`）：

- 项圈端每帧带一个 1 秒窗口端侧动作识别结果（`esp32_mlp`，标签为 standing / sitting / lying down / walking，置信度 0.6–1.0 才有效）。
- 服务端收到相邻两帧（同一开机周期、间隔 ≤3 秒）时，把这段间隔按**前一帧**的动作标签记账：walking 计入走动，standing / sitting / lying down 都计入静止。
- 间隔 >3 秒（音频上传阻塞、网络抖动、设备重启）或识别置信度不足的时段只计入"已观测"，既不算走动也不算静止。
- "今日"按北京时间零点起算。

"感觉不准"的实际构成（用 Marni 当天数据验证：已观测 1 小时 33 分，走动 2 分 12 秒，走动+静止覆盖已观测时长的 99.4%）：

1. **识别口径**：静止是"站着 + 坐着 + 趴着"三类的合并；原地挪步、缓慢踱步、趴着翻身在 1 秒窗口上区分度低，大多被归入站立/趴下 → 静止。走动偏小主要来自这里，不是断线漏计。
2. **归账滞后**：0–3 秒的间隔整段记给前一帧标签，起步的前几秒容易被记成静止。
3. **不可见的空洞**：项圈离线/充电/上传阻塞时段没有任何数据，页面只有一个"已观测 X"，用户无法区分"它没动"和"没数据"。
4. **今日边界**：项圈今天 10:43 才上线，之前的活动不存在，但页面没有任何提示。

结论：数字本身是诚实的，但**页面没有给出足以自查的上下文**（什么时候走了、哪里没数据、口径是什么），"不准"是呈现问题大于算法问题。动作识别模型的精度优化超出本次 UI 改版范围，设计上以"估算"标注口径。

### 1.3 "圆形宠物、动画互动、声音、项圈排列丑；'动画互动'按钮蠢"

现状 PetHero 区从上到下 5 层：232pt 双描边圆 → 动作徽标 → "动画互动"独立按钮 → "安静"声音胶囊 → "项圈在线 76% ›"文字行。问题：

- 横构图的角色卡塞进竖向圆形，两侧大量空白；三层描边/徽标叠在圆上。
- 状态分散在 4 个互不相关的小控件里，同一信息出现两次（动作徽标 + 状态行）。
- "动画互动"是一个带文字的按钮：互动应该是**点宠物本身**这个自然手势，独立按钮既占空间又教条。
- Hero 区总高度几乎占满首屏，健康体征和今日记录被挤到第二屏。

## 2. 设计原则

1. **首屏回答两个问题**："它现在怎么样"（Hero + 体征）与"今天过得怎么样"（今日记录）。Hero 压缩到一屏内让位给数据。
2. **宠物即界面**：互动走自然手势（点它），不设说明性按钮；状态聚合成一条，不重复。
3. **诚实呈现**：无数据显示原因与建议；估算值标口径；不可靠的传感器字段不上界面（延续仓库"不做前端假数据"约定）。
4. **摘要 + 入口**：今日页不重复记录页的完整图表，给摘要和跳转。

## 3. 页面结构（自上而下）

### 3.1 顶部

保留：日期 + 通知铃铛 + 问候语（"中午好，Marni！"，rounded 字体）。问候是品牌情感位，不动。

### 3.2 宠物 Hero + 实时状态条

- 圆形 232pt → 约 180pt，去掉内侧第二层描边，只保留一圈在线状态环（在线绿 / 离线灰）。
- 动作徽标（"正在站立"）保留在圆下沿——宠物即状态。
- **删除"动画互动"按钮**：轻点宠物身体播放当前动作的互动（转头）动画，4 秒后恢复；吠叫时自动切吠叫动画并优先于互动（沿用现有优先级与素材回退逻辑）；离线时长按切换预设动作的预览能力保留，入口提示改为一次性轻量文案（如"点点它，跟它互动"），不再常驻按钮。
- **新增状态条**（原声音胶囊 + 项圈状态行合并，一行三枚可点胶囊）：
  - `[● 项圈在线 · 76%]` → 跳项圈状态页（未绑设备时显示"绑定项圈"引导）
  - `[正在站立]` → 动作说明（可选：弹测量说明）
  - `[声音安静]` → 跳记录页声音时间线；吠叫时高亮为"正在吠叫"
- 效果：Hero 区 5 层 → 2 层（圆 + 状态条），预计省出约 120pt 纵向空间。

### 3.3 健康体征卡

- **主行 3 项核心体征**（心率 / 血氧 / 传感器温度），每项包含：
  - 当前值（大字，tabular-nums）+ 单位；数据新鲜时来自实时帧，否则回退显示"今日均值"并标注。
  - 今日区间小字（"今日 52–111"，来自服务端日聚合）。
  - 60 分钟迷你趋势线（sparkline）：数据新鲜时用 `useTelemetry()` 已有的内存序列，无实时时回退当日小时桶；不新增后端。
  - 状态角标：正常 / 偏高 / 无数据，参考区间按宠物档案的物种给默认值（仅状态点 + 说明文案，不做医学断言）。
- **次级行**：环境温度（新增，见 §5）· 项圈电量 · 最近更新时间。
- **无有效读数态**：三个 "—" 改为一句解释 + 建议（"项圈在线，传感器暂未读到有效数据，请检查佩戴贴合度"），保留偏高警告条与"测量说明"折叠。

### 3.4 今日记录卡（走动/静止重做）

- 头部保留"今日记录 · 已观测 1 小时 33 分"。
- **新增活动时间轴**：一根横条画今日（北京时间 0 点 → 现在），三态——走动（品牌橙/绿强调）、静止（浅底）、无数据（留白/斜纹）。空洞直接可见，回应"不准"的感受。
- 数字行：走动 2 分 12 秒（占已观测 2%）· 静止 1 小时 31 分。声音次数按决策留在记录页。
- 口径脚注（小字）："按项圈动作识别估算，仅统计项圈在线且识别有效的时段"。
- 整卡点击仍进记录页（保留现有跳转与文案链接）。

### 3.5 运动日记入口

保留现状独立卡（已有 petgif 条件文案），弱化视觉高度。

## 4. 交互与状态细节

| 状态 | 行为 |
| --- | --- |
| 项圈在线、数据新鲜 | 体征显示实时值 + sparkline；状态环绿色；动作徽标随帧更新 |
| 项圈在线、健康无效（全 0） | 体征区解释文案；状态环绿色；徽标正常 |
| 项圈离线/无帧 | 状态环灰、状态条显示"项圈离线"；体征回退日聚合（标"今日均值"）；时间轴显示离线空洞 |
| 未绑定设备 | 状态条首枚变"绑定项圈"引导，体征与记录卡显示建档引导（沿用现有空态） |
| 吠叫识别 | 声音胶囊"正在吠叫"高亮 + 宠物吠叫动画（置信度 ≥0.6，沿用现有判定） |
| 回放模式 | 保留现有回放提示卡与"实验中的读数"卡，不参与本次改版 |

## 5. 数据与最小服务端改动

| 改动 | 说明 |
| --- | --- |
| `observations.py` day 桶增加 `walkingSeconds` / `stationarySeconds` | 支撑活动时间轴；分钟表已有按动作秒数，聚合是加法，无迁移 |
| `METRICS` 增加 `envTemp` | 帧里真实存在（Marni 当前 31.2）；JSON 字段，无迁移 |
| summary 可选增加最近一次走动区间 | "最近走动 13:40–13:52"，由分钟表连续 walking 段推得；一期可不做 |

客户端：sparkline 用 `useTelemetry().series`（已在内存）+ day 桶回退；不改遥测解析服务；不新增依赖。

## 6. 验收

- 有数据 / 在线无有效读数 / 离线 / 未绑定 / 回放五种状态视觉与文案正确；时间轴在"全天离线"与"部分观测"下渲染正确。
- 轻点宠物播放互动动画、吠叫优先、长按离线预览、素材失败回退不回归（扩展现有 pet-avatar 选择器测试）。
- 声音胶囊、项圈胶囊跳转正确；状态条在窄屏（320px）不换行溢出。
- `npm run lint`、`typecheck`、`format:check`、`npm test`；服务端 `python -m unittest discover -s server/tests`。
