# 趋势统计完整修复设计

日期：2026-10-25。工作分支：`codex/fix-trend-statistics`。

## 目的与范围

让宠物家长能够准确理解心率、血氧、体温在所选时间范围内的变化、真实极值和记录覆盖情况。用户已选择前后端完整修复。只修改趋势相关接口、聚合逻辑、首页趋势卡和必要的共享类型/组件；不修改宠物资料、定位、告警规则和音频展示。

沿用 Flask、React Native/Expo 57、react-native-svg 和现有主题，不新增图表依赖，不修改原始遥测帧解析，不增加数据库表。Expo 57 版本文档已读取。所有展示来自本人设备的有效真实记录。

## 方案选择

1. 仅修前端：改动小，但服务端缺少血氧、体温极值，无法纠正统计结果，未采用。
2. 前后端统一统计与展示：保留现有归档及 readings，修复聚合、数据契约和交互。用户已选择此方案。
3. 新建长期时序存储：能改善历史完整性，但涉及采集、迁移和运维，超出本次修复。

以下细节为实施建议，尚待用户批准。

## 时间与数据规则

- 对外时间戳为 ISO 8601 UTC；自然日和图表标签按 Asia/Shanghai。使用带时区转换，不手动加八小时。
- 24 小时：精确滚动窗口 `[now - 24h, now]`，按北京时间整点分桶，首尾桶可为部分小时；保留完整桶序列，通常 25 桶。标签展示真实日期/小时，跨日不能混淆。
- 7 天、30 天：包含今天在内的北京时间自然日；今天只统计到当前时间。
- 全部：截至当前的所有可用记录，按自然日聚合。返回起止日期和实际记录范围；不承诺不存在的完整历史。
- 所有区间统一合并本人设备实验根目录 `health.csv` 与实时 readings；不扫描事件子目录，避免同一实验记录的重复副本。
- 以设备 ID、归一化接收时间及归一化三项健康值识别归档/数据库的同一条健康记录。归档和数据库接收时间来自 ingest 中同一次 store 调用；保留微秒精度，不按设备开机时间去重，避免重启冲突。相同值但不同接收时间属于不同采样。
- `valid` 必须为真。每项指标独立接受有限正数，拒绝布尔值、NaN、Infinity、非数值；单项缺失不丢弃其他有效指标。不根据医学阈值删去异常值。
- 不填补缺失值，不把缺失当零，不把未知覆盖时段当正常。展示“有记录 X/Y 个小时（天）”，这表示桶覆盖而不是连续佩戴时长。
- 保持设备归属隔离；无设备只返回空桶和空统计。无效 period 返回明确的 400。

## 服务端统计与接口

- 每项指标维护独立 count、sum、min、max；统计使用原始精度，只有最终展示才四舍五入。
- 区间平均 = 所有有效样本总和 / 该指标样本总数。区间最低/最高来自原始样本，不从桶均值推导。
- `samples` 统一为至少一项有效健康值的去重帧数，不再把三项指标数量相加；每项指标另有独立 count。
- 接口保留现有 `avgHr/minHr/maxHr/avgSpo2/avgTemp` 等兼容字段，补齐各项极值及计数；新增版本化的 summary、窗口起止、桶起止、generatedAt、记录范围和覆盖信息。客户端以新统计字段为准。
- 固定区间补全空桶，空桶的数值为 null、计数为 0。全部历史可以返回稀疏日桶，客户端按真实时间定位并显式断开空缺日期；避免构造无限长的空桶列表。
- 归档缓存按设备集合与文件路径、mtime_ns、size 失效；实时 readings 每次读取。缓存有界并定期失效；新增归档、文件追加、设备更换立即影响下一次请求。
- 以一次请求捕获的 now 作为所有窗口边界，过滤未来记录。归档损坏/读取错误不能静默伪装成完整历史：响应附可读的部分数据提示，无法提供数据时返回可重试错误。

## UI 与交互

趋势卡从首页中抽成独立组件，默认展开，让图表及统计可直接发现。保留收起入口，并保留当前选择；不改变其他首页区域。

布局从上到下：

1. “健康趋势”标题、刷新按钮和展开/收起按钮。
2. 心率 / 血氧 / 体温分段选择；24 小时 / 7 天 / 30 天 / 全部范围选择。
3. 当前范围日期、按小时/按天均值说明。
4. 带单位的“平均 / 最低 / 最高”，全部来自区间 summary。
5. 图表：按真实时间位置绘制直线和点；缺失桶断线；单桶也显示一个可选点，不显示“等待数据”。纵轴采用可读且不重复的刻度；不使用平滑插值制造未观察到的变化。
6. 点击或轻触图表，选择最近时间桶：显示该桶的明确起止时间、平均/最低/最高和有效样本数。选择缺失桶显示“此时段暂无有效记录”。不要求 hover 或长按，不与页面纵向滚动抢手势；为辅助功能提供可访问的上一时段/下一时段按钮及选中状态。
7. 实际记录覆盖、最近更新时间和历史来源说明。历史不足时直接说明，不用宽泛“等待数据”。

坐标与布局规则：X 轴覆盖整个所选窗口；标签去重并在跨日时带日期；Y 轴绘图区留出标签边距，常量序列也使用合理刻度。点击提示显示在图表下方，不被悬浮加号遮挡；趋势卡底部保留足够 TabBar 安全距离。颜色来自 theme；浅色/深色保持对比。

## 加载、刷新与一致性

- 首次加载显示明确加载态；切换时间范围时清除上一范围数值或标记加载，不能把旧范围统计放在新标题下。
- 成功但 0 个有效样本：显示“此范围暂无有效记录”，统计为 `--`。单项无数据不影响另外两项。
- 请求失败：显示“趋势加载失败”和重试按钮；刷新失败可保留同一用户、设备、区间的旧数据，但明确显示“更新失败，当前为上次记录”。
- 屏幕聚焦时刷新；前台且趋势展开时每 60 秒刷新，切回前台立即刷新。收起后停止定时请求，展开即刷新。
- 首页下拉刷新同时刷新看板和趋势；趋势内刷新只更新趋势。自动刷新不抢占用户正在查看的桶。
- 用户、设备、范围切换时取消或忽略旧请求结果；退出登录清空数据。后台不轮询，同一查询不叠加定时请求；手动刷新必须能使当前查询重新获取数据。
- 切换指标/范围重置桶选择；同一范围刷新后按桶时间保留选择，桶离开窗口时清除。
- 新客户端兼容旧接口：缺少新 summary 时明确显示“需要更新服务端以查看完整趋势统计”，不再计算错误的极值。旧客户端仍可使用兼容字段。

## 验证与验收

服务端回归：设备隔离、鉴权、无数据、单点、不等采样数的加权均值、各指标真实极值、部分指标缺失、重复归档/DB、跨日与 UTC 偏移、24h 边界、7/30 天当日多小时合并、全部区间含实时记录、坏文件、非有限值、缓存追加失效、无效 period。

客户端纯逻辑回归：空桶/单点、断线、按时间定位、非重复刻度、区间统计与选中桶统计、过期请求隔离。刷新/切换及展示通过 computer use 验证。

运行 app 的 lint、typecheck、format:check、现有与新增测试、Web 构建；服务端运行完整 unittest。随后用 computer use 检查四种区间、三项指标、单点和无数据、重试/刷新、点选详情及纵向滚动。测试专用合成数据仅用于隔离测试，不进入产品数据源；产品截图使用已有真实数据。

原工作区保持不变，所有实现只在独立 worktree；本次交付代码和验证结果，不合并 main 或部署。

## 已知限制与实施裁量

readings 是约 10,000 条的环形缓冲，实验归档只在录制时存在。本次不会补回已被删除且未归档的数据。UI 必须公开这一覆盖限制。

文件归档很大时首次全量扫描仍有成本。实现者可在不改变统计语义和去重保证的前提下选择有界缓存、流式读取和分桶内存结构；具体组件拆分、文案细节、刻度步长算法由实现者决定。
