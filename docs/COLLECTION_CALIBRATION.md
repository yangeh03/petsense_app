# 用户录像标注与时间校准

入口：登录 App → 我的 → 录像标注与校准（设备卡片下方）。

## 前提

- 在“我的”页认领项圈；采集页读取当前账号绑定的设备，不写死设备 ID。
- 手机录像使用原生 iOS/Android，相机与麦克风权限均需允许。Web 不提供录像。
- 项圈须运行支持 collection_v2 / collection_status / collection_arm 的采集固件。
  仅上报 edge_v1 分类结果的端侧演示固件不满足此条件，界面会保持采集不可用。
- App 和服务端均须包含本 PR，且 API_BASE_URL 必须指向同一个服务器。
  不需要向普通用户分发工程师 Bearer 密钥；使用现有 X-Petsense-Session 登录态。
- 新增 Expo 原生包和权限声明后，独立开发构建需重建安装，不能只推 OTA。
  Expo Go 的相机、声音、文件保存与回放仍需真机验收。

## 工作流

1. 连接并校时：5 次服务器时间测量选最短往返值，创建个人采集会话。
2. 开始项圈采集：发送命令后等待板端确认，查看 SD、落盘数、时钟和错误计数。
3. 录制晃动校准：手机录像，同时等待项圈确认静止后倒计时，晃动一次并结束录像。
4. 点动作标签开始正式录像；切换动作只追加标签区间，再点同一标签或结束录像停止。
5. 视频及 JSON 先写入 App 私有文件目录，不自动保存相册；每 5 分钟分段，段间不保证无缝。
6. 在本机录像列表点上传：512 KiB 分片、SHA256 校验、可重试续传；服务端完整解码确认后标记成功。
7. 已上传视频进入查看/对齐，暂停到可见晃动点，选择对应 IMU 标记并确认。
8. 原始 labels 不覆盖；alignment 保存视频-IMU 映射，aligned_labels 保存校正后的 UTC 动作区间。

项圈停止与手机录像停止是独立操作。离开页面时录像或上传中的返回被阻止；进入后台停止录像。
动作按钮有 800 ms 防抖，且仅在新鲜板端状态确认同一会话采集中时启用。
校准录像绑定独立 marker ID，回放只列出对应触发，后端也检查对应关系。

## 数据和权限

手机：documentDirectory/petsense-collection/<userId>/<videoId>.mov 和 .json。
旧实验版没有 owner_id 的本地录像不自动迁移到任一登录账号，避免账号间误泄漏。
云端：既有 collection 根目录下 <sessionId>/<videoId>/video.mov、annotation.json。
JSON 包含 session_id、事件区间、调用录像 API 时的时间估计、时钟不确定性和人工对齐结果。

个人会话在 document 内记录 owner_id，不改数据库表结构。每个视频接口均检查会话归属。
设备解绑/转移后，新用户不能读取旧用户录像，旧用户不能再向已转移的设备发控制命令。
工程师原有 Bearer 接口保持兼容；旧的无 owner_id 会话仅工程师访问，不自动认领。
请求必须通过 HTTPS，生产部署应同时检查上传大小、反向代理读写超时与存储配额。

## 精度边界

网络校时依赖往返延迟估计，不是严格误差上界；录像起点是 recordAsync 调用时间，不是首帧 PTS。
手动视频步进为 0.1 秒，IMU 10 Hz 采样的时间量化为 100 ms。人工视觉误差未测量。
单个标记只校正对应视频起点，不估计整场实验漂移，也不会自动校正其他视频。
不同视频若没有可见同步事件，仍只有初始网络校时估计；不能标为已人工校准。

## 测试与验收

新增服务端测试覆盖账号隔离、设备转移、全部视频接口越权拒绝、跨设备标记过滤和对齐时间转换。
发布前需在 iPhone 实测权限拒绝/重新授权、5 分钟分段、后台中断、弱网续传和画面-IMU 人工对齐。
此功能不会自动刷固件或自动开始正式采集；本 PR 不包含服务器直接部署。
