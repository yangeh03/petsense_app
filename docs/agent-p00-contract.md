# Agent P00 跨端最小契约与实施前提

2026-11-22 修订。本文定义 P01–P20 共用的行为与数据语义。具体载荷、表结构、时限和迁移步骤由后续 spec 确定。当前能力以[第一阶段实施记录](./agent-phase-one.md)为准。产品取舍、技术状态和开发前置条件分别见[产品设计](./agent-product-integration-design.md)、[技术选型](./agent-technical-decisions.md)、[实施路线](./agent-implementation-roadmap.md)和[工作包](./agent-implementation-work-packages.md)。

## 1. 运行、触发与授权范围

- 一次 Agent Run 由主人消息、已调度检查点、到期交付或获准的事件等触发。会话回合承载用户可见的消息，运行承载一次有界执行，长时间委托通过独立的持久任务衔接多次运行。运行可经历多轮模型和工具往返，前台等待和后台排队共享执行语义。
- 服务端在触发时解析并绑定实际授权用户、宠物、会话、主题及相关授权版本。前台来源为登录会话和已验证入口，后台来源为已保存且仍有效的任务或事件策略。模型收到的是受限上下文和可调用工具。工具执行从服务端取得授权主体，模型建议的标识仅作为待校验的目标引用。
- 每次调用先验工具是否启用、运行范围、用户与宠物归属、关联的会话或主题、参数形状、允许的操作及确认状态，以及次数、耗时和输出预算。执行前复核可能变化的授权。明确涉及另一主题时，经获准的检索工具查回同宠物的可访问记录，当前运行的授权范围保持受控。
- 模型在同一工具循环内根据上下文选择回答、澄清、读取工具、继续探索或提出行动。P05 替换当前单独的 `model.decide()` 和后续意图分支。自由文本语义由模型理解，既有明确的用户控件、资料权限、测量口径和已确认约束由代码执行。

## 2. 工具结果、时间与可验证交付

- 工具结果表达执行状态、结果引用、请求范围、有效数据范围、粒度、覆盖、缺口、算法或资料版本，以及可消费的证据。区分无有效观测、功能未开放、权限不足、执行失败与有效的零值。设备离线和缺测分别表达，两者也可能同时发生。比较前检查候选窗口、设备有效绑定和特征版本的可比性。
- 时间边界使用带时区的绝对时间，范围统一左闭右开 `[start, end)`。首版自然日及相对时段按明确注入运行的 Asia/Shanghai 解释，确认卡显示绝对起止及时区，运行中沿用冻结的时间基准。服务端按业务口径校验并以 UTC 储存绝对时间，覆盖率分母与实际窗口匹配。当前观测接口最长支持 90 天，分钟聚合支持分钟粒度的证据。发生时间不明时保留未知，接收时间和保存时间独立记录。
- 观测源、主人确认的资料、历史结果和网页各有来源类型。设备关联按时间上的有效绑定处理。来源携带可定位对象和时段，网页记录地址与核对时间。来源卡由运行时根据真实工具执行回执或本轮查回并重新授权的历史回执生成，客户端只打开约定的业务入口。
- 模型输出的事实性数字引用经过校验的证据标识，最终显示数值用对应的结构化结果和服务端口径。回复可解释已知事实、指出证据限度或请求澄清。缺失、越权和不存在的引用触发受限输出或失败处理。角色、来源、所宣称的任务或写入状态都须对照可确认的服务端结果。回复中的宠物拟人表达保留为对话。
- P01 维护观测及版本化覆盖，P05 负责最小只读工具及事实交付。UWB 点位、GPS 点位和已确认的房间语义分别建模，区域历史只来自获准且具有有效时间及版本的语义结果。

## 3. 会话、受控表达与接口兼容

- 会话属于授权主人与一只宠物。主人、爱宠和照料助手共享同一消息流，爱宠和照料助手使用同一事实版本。明确的 `@` 和回复指向以结构化元数据传入，主人可纠正当前发言对象。默认一位主要回应者，后续允许一次运行发布最多两位有序且互补的角色回复，现有 App 仍消费单条主要回复。角色消息和系统卡片不触发新的角色互答。
- 消息、回合、回复、主题和运行各有稳定标识。主题用于聚焦和恢复，可关联事件或任务。内容块按能力逐步支持文本、图片引用、来源、确认和结果。增量属于指定消息和运行，终态和重连恢复以持久记录为准，界面能对未知内容块做可理解的降级。
- P05 先沿用 `POST /api/app/agent/pets/<id>/turns`，请求包含 `text`、`requestId`、`target`、可选 `topicId`、`replyTo`。保持 `GET /api/app/agent/pets/<id>/turns?before=` 的历史和状态读回、既有分页、已读接口和观测来源跳转。兼容现有 `pending`、`complete`、`failed` 三类回合状态及文本、角色、来源字段。若内部增加运行状态或新交付结构，旧 App 继续按已有契约使用。扩展接口及传输方式留给对应 spec。
- 同一授权宠物和 `requestId` 的相同请求返回同一回合，正文、指向和两项关联属于请求身份。原请求是否送达不明时沿用旧标识和完整载荷，同键改动载荷返回冲突。服务端已确认失败时保留原话及关联，用户重试分配新请求标识。旧运行的失败状态保留，旧运行已提交的业务结果按效果键查回。对应到期回信或通知的重复投递也由稳定结果键去重。

## 4. 工作记忆、长期记忆与写入

- 工作记忆包含当前触发和授权范围、相关的宠物档案与主题消息、角色设置、上一步结果和可用的证据引用。注入范围有界，模型可按需检索获准的旧主题、观测或经历。运行检查点保存的是可恢复的运行进度。内容压缩保留归属、时间、确认状态和证据引用。
- 长期记忆由产品自己的存储管理。宠物档案归 pets 域，助手设定独立保存，已确认的经历和可追溯汇总进入 P09 的记忆。主人原话和传感器观测有各自来源与有效时间，生成摘要、角色表达、网页知识及推测保持各自的证据等级。旧消息可作为追问线索，正式资料采用当前有效版本。
- P07 定义候选、确认、冲突、修订、撤销与刷新，再由 P09 接入确认资料和经历的检索。提案具有稳定标识、主体、作用范围、版本、来源和有效期。普通陈述可提出内联确认。对象和值明确且无歧义的主动保存指令可作为一次授权，按 P07 的校验和审计执行。含假设、否定、其他主体或时间不明的信息保留原语义。
- 确认、修改和拒绝支持幂等提交，并校验候选版本。持久写入成功后展示完成并更新资料页和工作记忆。写入失败保留可继续处理的候选。修改或撤销事实后，相关摘要和回信按来源关系标记需更新或说明无法重算。

## 5. 任务、主动回顾和持久效果

- 初始个人基线按宠物、维度、粗时段和算法版本记录。P01 持续保存覆盖证据，P10 计算初始七个有效日、实际范围及是否可比。学习阶段可以查询事实和执行获准的事实观察，比较能力按具体维度和时段开放。
- 委托先提出结构化计划，展示目标、对象、绝对窗口、时区、检查及送达节奏、截止和缺测处理。主人确认后才创建或变更任务。确认后生效的计划版本和动作边界固定在任务中。暂停保留截止，恢复从当前时点开始，提前取消停止后续检查和交付。到期保存实际结果、覆盖不足或执行失败状态。模型生成失败时仍能交付已核验的状态，补写表达时引用同一个结果标识。
- P13 提供有持久游标、检查点和幂等的执行底座。P15 的观察、回顾委托在它之上运行。硬件能直接确认的事实与按证据得出的照料发现有不同来源。P14 的主动发现使用已授权的系统回顾或事件触发，沿用运行契约，合并同一事项。系统作业与主人确认的委托分别记账。已读和告警解除各自记录。
- 持久效果包括档案变更、任务状态转移、回信和通知交付。每项使用稳定的效果键，先核对原结果或正在执行的状态再恢复。模型重试、运行重启和通知重投各有独立的幂等边界。只有后端确认生效的效果才能作为已保存、已启动、已修改或已交付的依据。

## 6. 客户端、通知与追踪

- 今日、位置、伙伴、社区、我的为当前导航。伙伴为自然语言入口，`/records` 根据来源标识和时段定位，返回原消息或原入口。返回时恢复有记录的草稿、主题和滚动位置。P17 让今日预览、伙伴主题和铃铛引用同一交付对象，P18 负责原生推送和冷启动定位验收。社区沿用现有流程。
- 运行审计记录触发与运行标识、经脱敏的工具名与参数范围、执行状态、超限、失败阶段、引用、已确认效果和交付结果。保留必要版本与时间，凭据、私有推理链和无关正文排除在常规诊断之外。验收回放复用经脱敏的事件与工具样本，检查可见结论、允许行为和状态，允许模型换一种等价表述。

## 7. 给各 spec 的交接

P00 固定共享语义与边界。P05 首先以一个包含来源、失败与恢复的只读真实回合验证 Python LangChain `create_agent`／LangGraph 候选，在兼容载荷下验证旧前置路由的替换。生产现状仍是现有 MiniMax 适配器，[技术选型](./agent-technical-decisions.md)记录候选的实测范围及验收门槛。P07 先完成确认写入，P09 才能索引确认资料和长期经历。P13 先完成调度与恢复能力，后续包才开启后台运行。图片输入、搜索、区域语义与原生推送分别在 P11、P12、对应数据工具 spec 和 P18 验证，实际接入情况见技术选型与实施记录。
