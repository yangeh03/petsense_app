# Agent P00：跨端最小契约与实施前提

状态：设计契约草案，尚未实现或验证真实服务。产品和技术决策负责人：项目负责人（用户）；跨域接口、数据库迁移、App 导航、后台启动及外部服务决策均由其统筹。以下为 P01–P20 的共同语义，具体路径、字段类型、数据库结构、流协议由对应 spec 确定。

依据：[产品设计](./agent-product-integration-design.md)、[工作包顺序](./agent-implementation-work-packages.md)。

## 1. 主体与时间

- 所有数据查询、消息、记忆、事件和委托必须绑定当前授权用户与目标宠物；设备数据经设备归属及其有效绑定关系关联宠物，不把设备 ID 当作宠物 ID。历史设备换绑时的精确归属与可回填范围由 P01 根据实际可用记录定义，不能推断缺失历史。
- 发生时间表示观测或主人描述的实际时间，接收/保存时间表示系统处理时间；不明发生时间明确标记未知，不用接收时间冒充发生时间。时间点统一用带时区的绝对时间表示；按日/时段分组使用明确的用户时区，委托确认时保存计划时区及起止。
- 范围约定左闭右开 `[start, end)`，查询结果返回请求范围、实际覆盖、缺口、数据版本与来源；无数据、设备离线、零活动分别表达。不同算法、区域定义或绑定时期不自动视为可比较。
- 现有 `TelemetryMinute` 按用户、设备、分钟存储，`TelemetryEvent` 保存声音事件；现有周/月接口部分内容仍按今日组织。P01 负责新的统一查询语义。UWB 区域语义由定位侧提供，成功解算并生成语义后才能记录区域历史。

## 2. 会话、消息与内容

一次会话属于一位主人和一只宠物，包含主人、爱宠、照料助手三种发言身份；主人消息发起一个回合，回合关联零至两条有序角色回复。消息、回合、主题均有稳定标识，回复关系和 @ 指向是独立元数据。主题是会话内聚焦上下文，可关联事件或委托；主题追问本身不创建任务。

消息正文由可扩展内容块组成，首批约定文本、图片引用、来源、确认提案、事件和任务结果。未知内容块应安全保留并显示可理解的降级提示。客户端发送提供稳定请求标识，服务端对同一意图的重试去重；生成失败保留主人原话。历史按稳定顺序分页，支持指定消息定位。

流式回复的语义包括开始、增量、完成、失败；增量属于指定消息和回合，重连后以服务端已保存结果为准。具体传输与断点恢复机制留给 P02/P03 spec，不假设已有实现。模型或角色产生的消息不会自动触发角色互答。

示意（字段名仅表达语义）：

```json
{"conversation":"c1","turn":"t1","message":"m1","speaker":"owner","topic":null,"mentions":["pet"],"blocks":[{"type":"text","text":"今天走动多吗？"}],"status":"complete"}
```

## 3. 查询、来源与共享上下文

只读工具按宠物、维度与时间窗口返回事实、覆盖情况、时间范围、版本及可定位来源；不在来源不足时编造结论。来源区分设备观测、主人确认的信息、历史结果和外部网页；引用记录提供可跳转的对象及时间窗口，网页来源提供地址和核对时间。

编排器先做话题范围与意图判断，再按需调用允许的工具；显式指向优先，其次当前主题，再按意图选择角色。每轮默认一位主要回应者，必要时最多两位；两个角色读取一致的共享事实版本。宠物陪伴语句不成为事实，外部知识不自动成为本宠事实。

## 4. 资料、记忆和确认

宠物结构化资料以 pets 域为真值；助手名称与语气等属于独立设定；经历、摘要和来源可进入长期记忆。明确且无歧义的“记住/更新”指令可直接写入并展示结果；普通陈述作为可忽略、可编辑的候选，经确认后写入。假设、否定、其他主体和未知日期须保留原意。

确认提案应有稳定标识、主体、候选内容、版本与状态；确认、修改、拒绝须能应对重复提交。写入成功后再展示成功，并刷新资料页与共享上下文；失败保留候选。生日、模糊年龄和带日期体重的具体字段及冲突策略由 P07 定义。

## 5. 基线、事件和委托

- 基线按宠物、维度、粗时段、版本分别记录进度与可比性；初始七个有效日是产品要求，各时段是否可比较独立判断。学习状态和实际覆盖来自同一服务端结果；未就绪仍能查询事实，但不输出成熟的个人比较。P01 先保存证据，P10 负责计算和重算。
- 默认发现由系统规则独立产生，事件有稳定实例、状态、来源统计、发生/更新时间及恢复信息；规则 ID 不是事件实例 ID。已读是消息状态，不代表告警恢复。
- 委托由主人确认具体计划后创建，含计划版本、范围、开始/截止、时区、检查或回信安排及状态；暂停不自动延长截止时间。进展与最终结果记录已观察范围和缺口。后台持久游标与稳定结果键负责恢复和去重；具体状态机由 P13/P15 定义。
- 系统汇总和默认检测作业不显示成主人委托；事件和委托结果可关联同一主题，并由同一消息交付入口承接。

示意：`主人提案 → 待确认计划 → 已确认委托 → 观察片段 → 到期结果 → 原主题追问`；未确认计划不启动。

## 6. 客户端与通知

导航目标为今日、位置、伙伴、社区、我的；记录为 `/records` 二级页面。记录定位携带日期、指标、时间范围及返回来源；伙伴主题、铃铛与今日预览引用同一消息或事件，保留草稿、滚动与主题。设备告警仍可定位设备或记录，社区保持现有路径。

当前代码仍是旧 Tab 排列，当前铃铛依赖前端本地告警；它们不是上述能力已实现的证据。Agent 业务消息使用独立服务，不能混入现有遥测解析器。通知持久化、已读、原生推送、冷启动定位由 P17/P18 完成。
