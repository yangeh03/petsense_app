# Agent P00：跨端最小契约与实施前提

状态：最小语义契约；2026-11-22 随[设计 V11](./agent-product-integration-design.md)（以 Agent 为设计对象）刷新，阶段 1 实际状态见[实施记录](./agent-phase-one.md)。产品和技术决策负责人：项目负责人（用户）；跨域接口、数据库迁移、App 导航、后台启动及外部服务决策均由其统筹。以下为 W 系列工作包（[工作包顺序](./agent-implementation-work-packages.md)）的共同语义，具体路径、字段类型、数据库结构、流协议由对应 spec 确定。

V11 兼容对话和后台运行沿用单 Agent 运行循环。双 Agent 群聊的路由、独立角色运行和消息契约见[群聊设计](./agent-dual-agent-chat-design.md)。工具由共同注册表声明和执行，按运行形态与角色校验权限。

## 1. 主体与时间

- 所有数据查询、消息、记忆、事件和委托必须绑定当前授权用户与目标宠物；设备数据经设备归属及其有效绑定关系关联宠物，不把设备 ID 当作宠物 ID。历史设备换绑时的精确归属与可回填范围由统一观测查询（阶段 1 已交付，W01 注册为工具）根据实际可用记录定义，不能推断缺失历史。
- 发生时间表示观测或主人描述的实际时间，接收/保存时间表示系统处理时间；不明发生时间明确标记未知，不用接收时间冒充发生时间。时间点统一用带时区的绝对时间表示；按日/时段分组使用明确的用户时区，委托确认时保存计划时区及起止。
- 范围约定左闭右开 `[start, end)`，查询结果返回请求范围、实际覆盖、缺口、数据版本与来源；无数据、设备离线、零活动分别表达。不同算法、区域定义或绑定时期不自动视为可比较。
- 现有 `TelemetryMinute` 按用户、设备、分钟存储，`TelemetryEvent` 保存声音事件；现有周/月接口部分内容仍按今日组织。统一查询语义由阶段 1 交付的 `agent/observations.py` 承担。UWB 区域语义由定位侧提供，成功解算并生成语义后才能记录区域历史。

## 2. 会话、消息与内容

一位主人的每只宠物可以有多个彼此独立的会话（W16，`agent_conversations`），每个会话包含主人、爱宠、照料助手三种发言身份，模型历史只取当前会话；主人消息发起一个回合，回合关联零至两条有序角色回复。消息、回合、主题均有稳定标识，回复关系和 @ 指向是独立元数据。主题是会话内聚焦上下文，可关联事件或委托；主题追问本身不创建任务。

消息正文由可扩展内容块组成，首批约定文本、图片引用、来源、确认提案、事件和任务结果。未知内容块应安全保留并显示可理解的降级提示。客户端发送提供稳定请求标识，服务端对同一意图的重试去重；生成失败保留主人原话。历史按稳定顺序分页，支持指定消息定位。

流式回复的语义包括开始、增量、完成、失败；重连后以服务端已保存结果为准。App 直连服务端 WebSocket 通道按用户和宠物接收状态，断线可降级轮询。兼容协议的发送使用同步 POST 和稳定请求键。所有协议中，角色发言均不会自行开启下一轮。

双 Agent 使用 `group-v1`。GET 和 WebSocket 在查询参数声明 `protocol=group-v1`，POST 在正文声明。支持新协议的客户端默认启用，发送返回 202 后异步交付。快照含 `messages`，每条有稳定 `id`、`role`、`position`、`status`、`version`、`text`、`blocks` 和 `sources`。WebSocket 的 `message`、`message_delta`、`message_status` 按独立消息对账，同一版本内正文为累计追加，改写带更高版本。精确引用同时携带 `replyTo` 和 `replyToMessage`，由服务端验证关联。回合重试保留已完成消息并继续失败项。

示意（字段名仅表达语义）：

```json
{"conversation":"c1","turn":"t1","message":"m1","speaker":"owner","topic":null,"mentions":["pet"],"blocks":[{"type":"text","text":"今天走动多吗？"}],"status":"complete"}
```

## 3. 运行、工具与共享上下文

Agent 以「运行（Run）」为最小调度单元：触发（消息/检查点/定时/硬件事件）→ 组装工作记忆 → 推理与工具循环 → 结构化交付 → 轨迹落库。兼容对话在运行内判定范围、意图和发言人格。双 Agent 先持久化路由范围和角色计划，再为每条角色消息各建运行，交付身份由服务端固定。每次运行的 `AgentRun` 记录消息序列、工具调用与结果摘要、判断结论与预算消耗，可回放和审计。轨迹不对 App 开放。

系统能力以**内部 Function Calling 工具注册表**暴露：声明（名称/描述/schema/权限级别/适用运行形态）与确定性执行分离注册；新增能力 = 注册工具 + 更新系统提示与权限矩阵，不新增代码分支。**权限矩阵先于执行校验**（运行形态 × 工具组 × 确认状态），越权调用返回结构化拒绝并入轨迹；`out_of_scope` 结论下业务与网络工具全部不可用。**已确认例外（W06，2026-11-22 负责人确认）**：供应商内建 `web_search`（MiniMax Responses API 服务端工具）在模型推理过程中执行，无法像 function 工具那样「先于执行」拦截；缓解措施 = 按轮挂载（stance 为 `out_of_scope` 后从后续轮次摘除）+ 运行结束审计标记（`search_on_out_of_scope`）+ 行为评测锁定 + 确定性限次（每运行累计 2 次后不再挂载），细节见 [W06 spec §2.1](./agent-w06-spec.md)。工具不向模型抛裸异常，失败返回结构化原因。动作类工具（设备控制、日记生成、社区草稿）与写提案类工具带确认门，只有「明确指令」或「已确认提案」两种生效路径。

每次对话运行注入**常驻快照**（有界）：宠物档案摘要、设备状态、当前动作与体征、当前位置、今日摘要、学习进度、活跃目标、助手设定，各来源带时间戳与有效性；过期或失效状态如实呈现，不当作当前事实。快照之外的细节由只读工具按需获取。工具按宠物、维度与时间窗口返回事实、覆盖情况、时间范围、版本及可定位来源；不在来源不足时编造结论。来源区分设备观测、主人确认的信息、历史结果和外部网页；引用记录提供可跳转的对象及时间窗口，网页来源提供地址和核对时间。

爱宠与照料助手是同一 Agent 的两个输出人格：显式指向优先，其次当前主题承接，再次意图；每轮默认一位主要发言者，必要时最多两位，是否双答由模型判断。两位人格读取一致的共享事实版本。宠物陪伴语句不成为事实，外部知识不自动成为本宠事实。

## 4. 资料、记忆和分级写入

宠物结构化资料以 pets 域为真值；助手名称与语气等属于独立设定；经历、摘要和来源可进入长期记忆。**记忆写入分两级**（V11 选型确认）：

- **自主写**：主人讲述的生活经历、事件与变化主题、习惯候选、会话要点、委托回信归档、日/周汇总——Agent 判断值得记时经 `write_memory` 直接写入，带来源、时间与可回滚版本，写入动作进轨迹，可选轻量回显。主人明确要求忘掉时经 `forget_memory` 将条目置为 retired（保留可审计、幂等），后续不再引用。
- **确认写**：宠物档案结构化字段（生日、体重、品种、名字等唯一真值）与长期偏好——经 `prepare_*` 提案与确认卡；明确且无歧义的「记住/更新」指令视同确认，直接写入并展示结果。

假设、否定、其他主体和未知日期须保留原意不写入；判定由模型结构化提案，业务服务落库前复核。记忆检索为结构化条件 + summary 关键词（SQLite FTS5 trigram）；记忆新表以 SQLite 为唯一目标。记忆整理含认识卡蒸馏（晋升决策入轨迹）与 markdown 报告导出（DB 为真相、报告为视图）。确认提案应有稳定标识、主体、候选内容、版本与状态；确认、修改、拒绝须能应对重复提交。写入成功后再展示成功，并刷新资料页与共享上下文；失败保留候选。生日、模糊年龄、带日期体重、提案版本和 decision 端点见 [W03 spec](./agent-w03-spec.md)。W04 实现经历与习惯候选等自主写，并预留长期偏好的确认写接口。助手设定属独立直写：`prepare_role_settings` 工具 + `GET/PATCH /api/app/agent/assistant-settings`（设定页读写，PATCH 白名单校验），语义见 [W03 spec §3.7](./agent-w03-spec.md)。

## 5. 基线、事件和委托

- 基线按宠物、维度、粗时段、版本分别记录进度与可比性；初始七个有效日是产品要求，各时段是否可比较独立判断。学习状态和实际覆盖来自同一服务端结果；未就绪仍能查询事实，但不输出成熟的个人比较。基线是确定性统计工具（`read_baseline`），不是判断大脑；阶段 1 已保存证据，W05 负责计算和重算。
- 主动发现由两种运行形态承担：**回顾运行**（每日/每周定时，Agent 判断「什么值得说」并合并入已有主题）与**事件运行**（低电、失联、长期无有效读数等硬件事实由确定性规则触发，Agent 决定打扰与表达）。事件有稳定实例、状态、来源统计、发生/更新时间及恢复信息；规则 ID 不是事件实例 ID。已读是消息状态，不代表告警恢复。
- 委托计划是**由 Agent 生成的语义化结构对象**（关注维度、条件语义描述与结构化近似、时间窗口、回信安排、结束条件），不限于预设模板；经主人确认后创建，含计划版本、范围、开始/截止、时区、检查或回信安排及状态；暂停不自动延长截止时间。执行器只做确定性调度、窗口数据物化、游标与去重；**检查点运行**由 Agent 按目标语义评估继续观察/值得提醒/回信，评估不修改已确认的计划参数。进展与最终结果记录已观察范围和缺口。后台持久游标与稳定结果键负责恢复和去重；具体状态机由 W08/W09 定义。
- W08 的 `read_task` 提供本宠委托及交付的鉴权只读查询，`propose_task_change` 仅在对话运行中生成候选。用户决定及直接委托簿操作在业务层校验归属、当前版本与状态。检查点运行只获得相应事实读取权限，由受约束的交付服务校验及持久化提醒、回信和归档。后台交付与手工对话共用 Agent 消息通道。版本、覆盖、去重和确认细节见 [W08 spec](./agent-w08-spec.md)。
- W09 的 `review` 与 `event` 只允许相关事实读取（观测/实时状态/档案），主动程度在交付时校验；对话形态新增 `read_care_topics` 供「为什么提醒我」类追问引用主题与依据。后端向新客户端声明已接管的设备规则（`GET /api/app/agent/pets/<id>/care/rules`，三类：低电/失联/长期无效），主题与结果使用稳定标识（`GET …/care/topics`）。回顾日界、硬件事件、去重和兼容详见 [W09 spec](./agent-w09-spec.md)。
- **W11（2026-11-23）**：个人基线比较对 `review` 形态开放（`read_baseline`），`event` 形态权限不扩大。比较单元统一为「维度 × 日期 × 粗时段」：同维度、同时段、覆盖达标且实际值严格超出 W05 的 p10–p90 才可作为个人变化候选（边界值等于 p10/p90 视为范围内）。模型输出以 `evidenceId` 引用候选，服务端校验引用、方向与数值，不符即拒绝并回退绝对事实描述。基线未就绪时，确认卡由主人明确选择「等基线就绪」或「先记录绝对事实」，缺少明确选择的新版候选不静默生效。交付时冻结样本窗口、基线版本与修订号、分位数、实际值与覆盖，历史回信按原证据展示（读取时不重算比较）。详见 [W11 spec](./agent-w11-spec.md)。
- W10 的 `control_device`（仅录音）与 `create_diary`（生成/重生成）每次执行均需已确认提案；读取已有日记可以直接执行。明确要求保存时 `draft_social_post` 可直接写本宠私有草稿，模糊请求走提案。三类动作只在对话中注册，正式社区发布由主人在既有发布页完成。稳定结果、设备录音协议和生产开关见 [W10 spec](./agent-w10-spec.md)。
- 系统汇总和回顾作业不显示成主人委托；事件和委托结果可关联同一主题，并由同一消息交付入口承接。

示意：`主人提案 → 待确认计划 → 已确认委托 → 观察片段 → 到期结果 → 原主题追问`；未确认计划不启动。

## 6. 客户端与通知

导航目标为今日、位置、伙伴、社区、我的；记录为 `/records` 二级页面。记录定位携带日期、指标、时间范围及返回来源；伙伴主题、铃铛与今日预览引用同一消息或事件，保留草稿、滚动与主题。设备告警仍可定位设备或记录，社区保持现有路径。

导航与记录下沉已在阶段 1 交付（今日、位置、我的、位置、伙伴、社区、我的；记录为 `/records`）；Agent 业务消息使用独立服务，不能混入现有遥测解析器。前端实现（V11 §18、W01）：自建消息渲染、列表与输入区；zustand 单例 store、AsyncStorage 轻量持久化、keyboard-controller 键盘协调。助手正文走流式文本，结构化内容走卡片。确认卡、执行结果卡等新内容块随对应工作包扩展。

### 6.1 W12 持久通知语义（收件箱）

- **来源与稳定 ID**：服务端在 Agent 域持久化收件箱索引，条目只存稳定来源引用（主题 id / 交付 id / 回合 id）、来源类型、时间与已读状态；**正文不进索引表**，读取时从原主题或回信水合。来源类型四类：设备事实 `device_fact`、关怀 `care`、到期回信 `reply`、学习完成 `learning`。幂等键 =（宠物，来源类型，稳定事件键）。
- **幂等与恢复**：条目由可恢复投影产生（水位 + 唯一索引）；重启、重投、并发写入不重复；恢复与初次迁移**不复活已读**。
- **启用（D5）**：启用时只补入当下仍开放的设备告警（历史补入标记，不触发系统通知、不追溯推送）；其余来源从启用后入箱；已关闭的历史告警不再补入，关闭的条目只刷新同一行。
- **预览（D2/D7）**：今日最多一条未读预览；优先级 = 仍开放的 **warning/critical** 设备告警 → 到期回信 → 可预览的关怀；同优先级取最新。**info 级设备告警永远只在收件箱**，不进预览。学习完成只进收件箱。安静档下未发布的关怀只在收件箱可见。
- **已读（D3）**：正常打开目标成功才自动标已读（单条幂等、全部已读按请求生效时的可见水位）；已读与告警解除各自持久化，**已读不解除告警**；404、他人 ID、离线与目标加载失败不标已读。
- **深链与冷启动（D4/D6）**：深链只携带收件箱 ID（`petsenseapp://inbox/<id>` → `/inbox/<id>`）；解析结果的参数带 `conversationId`（锚点回合所在的会话，已删除时不给），客户端先切到它再定位；登录后由服务端解析消息类型与目标（稳定路由 + 参数 + **锚点**：交付回合 id）。锚点可能不在会话已加载的一页或被话题过滤掉，此时按稳定回合 id 精确取回该条消息并展示；安静主题没有交付回合时展示权威主题本身。目标**展示后**才标已读；展示失败保持未读。跳转保留草稿、附件、话题与滚动位置，并提供回原会话/回收件箱的显式路径。未登录深链给出登录入口，登录后恢复同一路由；账号变更后到达的旧响应不应用。
- **账号与宠物隔离**：列表、详情、已读、解析分别校验条目归属与宠物归属；来源必须在同一账号 + 同一宠物下解析，否则给出明确不可用状态（换绑关闭的旧绑定不水合正文）。
- **与 W13 的接口**：推送候选 = 已交付 ∧（设备告警 ∨ 到期回信 ∨ 个人高相关三条件齐备：W11 冻结证据 + 模型明确 'high' + W09 已批准交付）；缺失相关性不得默认按 high；安静档不影响设备告警与到期回信；学习完成与一般关怀一律不是候选。W13 为 iOS 端，Android/Web 只保留收件箱。
