# W18 模拟器走查记录（2026-11-25）

走查对象：分支 `feat/agent-w18-dispatch-without-router`（commit `21ffa97` + 走查前的存量兼容与客户端占位改动）。
环境：iPhone 17 Pro 模拟器（独立设备 `W18-验收`，UDID `69E7A459-…`），iOS 26.5，Expo Go 58.0.7 + Expo SDK 58.0.20；
服务端为**隔离实例**：`PETSENSE_ROOT=/tmp/petsense-w18` 的 W18 夹具（端口 8097，模型桩不打真实接口，账号 `petsense`）；
客户端为 `main@dd51ffe` 的 app/（W18 未改客户端代码，仅改 `placeholderRole`）。

## 走查方式与限制（如实记录）

- 主人消息由**正式 REST 接口**发起（`POST /api/app/agent/pets/<id>/turns`，与 App 发送同一条路径），App 通过 **WebSocket 实时帧**收到并渲染；截图即 App 的真实渲染结果。
- **未做到**：在输入框里手打消息。原因是本机屏幕逻辑宽 1470，模拟器窗口放在 x=1430 处大半超出屏幕，`cliclick` 的鼠标事件被钳制、点不到模拟器窗口内；键盘事件可达（已用剪贴板粘贴填过登录表单）。登录最终用「把会话 token 写入 App 的 AsyncStorage 后重启」完成。
- 因此**未覆盖**：输入区发送按钮的点击、@ 选择器切换指向、图片上传（走查用预置图片）、键盘弹出时的布局。指向（target）由请求体的 `target` 字段给出，等价于用户在 App 里选好指向后发送。

**D2 语义核对**：默认模式下转交时，爱宠**留一句**（「这个我不懂，让照料助手帮你看看。」）+ 照料助手**再答一条**专业内容 —— 与负责人 2026-11-25 的确认一致（爱宠留一句 + 助手再答一条）。
**D1 语义核对**：只选爱宠时专业问题**只有爱宠一条**，它说不懂并建议问照料助手，不产生助手消息 ✓。

## 视觉走查（浅色 + 深色）

- 两个身份头像可区分（爱宠=爪印、照料助手=✳），主人气泡右对齐、品牌橙底；两个角色的气泡都是左对齐白底/深底，与既有伙伴页一致。
- 转交场景里爱宠那条与助手那条上下相邻、间距一致，头像不跳变，助手那条没有重复爱宠的话。
- 深色主题下文字与气泡对比正常，未见硬编码浅色底或不可读文本。
- 未覆盖的视觉项：生成中空气泡、转交失败态的「再试一次」按钮、来源卡（本次夹具场景没有真实工具来源）、上翻历史时的滚动位置。

## 与 W17（ZCode）的口径差异（本包按负责人确认取值）

W17 的 spec 写 D2 为「静默转接，爱宠不上屏」；本包按 2026-11-25 与负责人的确认取「爱宠留一句 + 助手再答一条」，因此截图里爱宠那条是可见的。两者不能同时成立，以本包为准。
