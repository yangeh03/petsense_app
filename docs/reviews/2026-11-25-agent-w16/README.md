## 环境

- 模拟器：iOS 26.5 / iPhone 17 Pro，独立设备 `W16-verify`（UDID `02A85AF7-0ABA-49E8-9D9C-D730EC05999B`）。
  这台设备是本次走查新建的：仓库里已有的 `W16-验收` / `W18-验收` 设备正被其它会话占用，Expo Go 的 dev server 会话会互相串。
- 服务端：**隔离实例**，本分支的 `server/tests/fixtures/group_fixture_server.py`，
  端口 8105，数据根 `/tmp/petsense-w16`，模型是夹具的确定性剧本（不打真实模型、不读模型凭据）。
  数据用 `w16_seed.py` 造：一只宠物「小白」、设备告警会话（项圈电量偏低）、周期回顾会话、一个带进行中委托的会话。
- 客户端：本分支 `app/`，Metro 端口 8097，`EXPO_PUBLIC_API_BASE_URL=http://127.0.0.1:8105`。
- 账号：`petsense` / `123456`（隔离实例）；另注册 `w16other` 验证换账号后的隔离。

## 走查方式与限制（如实记录）

- 功能判定走**无障碍树**（`idb ui describe-all`）与服务端访问日志；视觉判定走**设备截图**（`xcrun simctl io … screenshot`），两条通道互不替代。
- 中文输入用剪贴板粘贴（`xcrun simctl pbcopy` + `idb ui key 25 --command`，V 的 HID 键码是 25 而不是 9）；`idb ui text` 打不了中文。
- 走查期间该模拟器上有并发点击（别的会话在操作同一台机器），个别瞬时现象无法排除干扰，已在 spec 第 14 节标注为「未确证」。
- **未做到**：真实模型行为验证（夹具是确定性剧本）、存量迁移演练（隔离实例从空库起）、
  断线重连与轮询降级、Android 返回键关闭抽屉。

## 一句话结论

抽屉、多会话隔离、深链、改名/删除与 409 边界在模拟器上都能跑通；真实模型语义、存量迁移演练、断线降级三项仍未验证。
走查中发现并修掉了 4 个问题（夹具 `default` 剧本缺爱宠台词、409 文案缺空格、「回到原会话」无障碍标签带上图标名、空会话排序盖在有内容会话上面），
修复后在同一套环境里复验通过，详见 spec 第 14.7 节。
