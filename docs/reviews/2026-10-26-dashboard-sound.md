# Dashboard 声音设计复核与验收

## 问题与最终调整

1. 声音行原来仅在current=true（最近10秒有当前帧）时出现；用户看到的离线截图没有该行。改为永久可见的声音入口，未连接、未更新、准备中和未识别分别表达，有效声音显示安静/正在吠叫/正在嚎叫/疑似呜咽。点击进入已有诊断页，工程字段不挤占首页。
2. 片段数受分段算法、采样覆盖和模型波动影响，不是单声次数，没有日常基线，不能支撑异常判断。从首页移除该KPI，今日记录只保留走动、静止和观测覆盖。
3. 密集零时长片段缺少产品可读性。独立声音记录卡改为时间与声类；相邻检测相距不超过30秒合并一条，包含混合声类时列出实际检测到的声类。不显示累计叫声次数或虚构的连续时长。默认3条，更多按需展开，单条展开只看记录时间。
4. 独立代码复核指出通用遥测覆盖不能证明声音监听有效。采用中性“暂无声音记录”，避免把没有声音数据解释成没叫。

## 验证

新增声音状态与合并的4项行为测试，先RED后GREEN；覆盖quiet置信度0、离线、不绑定、准备中、低置信度、不同声类、乱序、不修改原始事件及30秒边界。

客户端全部28/28测试通过，lint/typecheck/format:check与Expo Web生产构建通过，git diff --check通过。服务端无改动，片段原始存储和兼容字段保持；没有新增统计指标或数据库迁移。

Computer use在独立本地账号和真实设备历史环境确认：中央形象保持，离线也有“声音未更新”按钮；点击进入诊断并看到历史声音warming_up/置信度0；今日记录没有片段计数；声音卡在没有当天数据时显示中性空态。没有修改真实账号或伪造新硬件帧。

实机持续在线的吠叫/嚎叫/呜咽逐项触发及误报率尚未验证，当前状态切换和事件分组以行为测试覆盖。声音列表基于API返回的最近20个原始事件，展示分组不是完整日历史；后续如需完整浏览需增加分页。没有异常阈值、情绪结论或可播放录音承诺。代码在codex/pet-data-experience worktree，未部署。
