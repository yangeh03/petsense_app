## 客户端与发布

- 使用 Expo SDK 58 `expo-notifications` 与 Expo Push Service。iOS 在已登录、权限允许且用户已开启时注册；使用项目 EAS project ID。提供已开启、系统拒绝、系统撤回、暂不可用和重试状态，保留收件箱入口。Android 和 Web 保持站内能力。
- 使用安装实例稳定 ID 与经认证的服务端绑定，处理同设备换账号、退出、token 轮换和设置关闭。客户端只向本服务端提交 token，日志中不打印 token、凭据或私人内容。同一安装的旧归属立即从后续发送集合剔除。
- 点击通知走 W12 统一解析，前台、后台和冷启动均按稳定收件箱 ID 定位。未登录时按登录续接处理。重复点击不会重复创建对象或影响未读语义。前台通知处理与系统行为对齐，同一次交付只有一个用户可见通知。
- 接入 SDK 58 原生配置，验证 iOS 应用标识、签名、设备注册与 APNs。使用原生新构建和 fingerprint runtime，旧客户端保持站内能力。服务端仅允许 iOS，默认关闭，保留快速停发手段。真实签名和凭据经 EAS 安全渠道管理。

## 服务端投递

- 只有从 W12 持久化的条目才能调度推送，使用 W08 持久作业基础和可审计的投递记录。键为收件箱条目与安装实例。发送前重新核对归属、开关、通知资格和 token 有效性，避免退出、切宠或权限撤回后的误发。发送载荷仅含通用文案、稳定收件箱 ID 和必要路由元数据。
- 保存 Expo 投递 ticket 与 receipt 结果，处理明确的服务方拒收、`DeviceNotRegistered`、超时及失效。仅在确定未接收且可恢复时执行有限重试。服务方是否接收未知、或进程在外部调用后且持久化前中断时，标记未知并停止该条发件重试。收件箱不受此状态影响。
- 安静档抑制非紧急主动推送，已明确委托的到期回信及关键设备告警仍依用户通知设置和服务端资格处理。高相关变化的证据引用与模型判断须与 W11/W09 落库记录相符。迁移补条目不进入发送队列。

## 验收标准

| 编号 | 功能与证据 |
| --- | --- |
| W13-A1 | 单测覆盖消息分类、安静档、资格复核、关闭平台、同一消息多设备、跨账号重新绑、退出和 token 轮换、重启和重复执行。 |
| W13-A2 | 测试票据成功、业务拒收、失效 token、明确的可恢复拒收、响应未知或请求后中断。核对所需重试与不重复发送，任何失败仍能在站内打开。 |
| W13-A3 | iOS 模拟器先验设置视觉、拒绝状态、通知响应入口和冷启动导航，使用 SDK 或本地受控注入。用浅色及深色截图对照原设置页的间距、控件层级、颜色与安全区。模拟输入只作为应用响应证据。 |
| W13-A4 | iOS 授权真机安装 EAS 内部分发构建。记录构建 ID、运行时、设备/OS、权限与票据结果。对允许的真实来源至少验证后台或冷启动送达及点击原对象、前台行为、通用锁屏内容、退出或禁用后的抑制、重复执行不重复提示。 |
| W13-A5 | 在授权隔离环境生成真实来源事件。生产账号只做安全范围内的核对。检查 Android 与 Web 继续使用收件箱，不请求远程通知权限、不注册推送。 |
| W13-A6 | 通过服务端全量 unittest、客户端全套检查和 Web 构建，核对 iOS 原生构建与对应 fingerprint OTA。记录部署、发布版本、iOS 开关和回退方式。 |

发布时分别记录服务端部署、Expo ticket、模拟器响应、OTA 和 iOS 真机推送。缺少签名、授权设备或端到端证据时，iOS 保持关闭并记录待验项。
